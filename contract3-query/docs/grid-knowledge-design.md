# 网格通业务知识库设计

## 目标

在现有“北京移动合约查询”中增加面向一线查询的网格通知识库。用户可以按业务 ID、业务名称、业务介绍、业务规则和资费表中的文字检索，并在 PC 与手机上快速打开完整业务资料。

## 已核实基础

- `data/grid-catalog.sqlite` 已包含 358 个业务入口、736 项业务、1,666 个内容分段和 2,137 行资费表。
- 现有 `/api/grid-catalog` 已提供分页列表、详情、状态和导出接口；列表查询会覆盖业务 ID、配置名称、标题、业务名称、介绍和规则。
- 业务原始入口继续通过现有 `/api/grid/open` 打开，知识库页面不保存或展示员工参数。

## 交互设计

1. 在“网格通业务大全”下增加“入口清单 / 知识库”两种视图。
2. 知识库视图默认展示入口卡片：业务 ID、标题、业务数量、采集状态和最近更新时间；结果总数与状态筛选保持可见。
3. 搜索框支持空格分词，输入后短暂防抖查询；查询结果按入口聚合，避免一个入口包含多个业务时重复出现。
4. 点击“查看知识详情”后懒加载详情，不在首屏加载全部长文本。详情采用 PC 侧栏、移动端底部抽屉的同一语义结构，包含：业务介绍、业务规则、资费表、动态资费标识和官方业务入口。
5. 长文本和表格只读展示，使用 DOM 文本节点渲染；图片仅使用采集结果中的安全图片地址。

## 技术方案

- 复用现有 SQLite 查询与 Node API，不新增数据库表和依赖。
- 首屏调用 `GET /api/grid-catalog?q=&status=&page=&pageSize=`，默认 20 条；详情调用 `GET /api/grid-catalog/detail?id=`。
- 详情在前端缓存，重复打开同一入口不重复请求；关闭详情不丢失搜索条件。
- URL 使用 `type=grid&knowledge=1&q=...&status=...&page=...`，支持分享和刷新恢复。
- 管理采集接口继续要求现有 Bearer 管理密钥；知识检索和详情保持只读。

## 性能与响应目标

- 列表只返回分页摘要，不返回长文本和资费明细。
- 搜索请求使用 180ms 防抖，并取消前一个请求。
- 详情懒加载并缓存，避免初始化时读取 3MB 以上导出文件。
- 目标：本地和已部署服务的知识列表首屏在 500ms 内返回；详情在 1s 内完成，超时显示可重试错误。

## 验收标准

- 能检索业务 ID、业务名称、介绍、规则中的关键词，并显示筛选总数。
- 能打开至少一个包含介绍、规则和资费表的详情；移动宽度下无横向页面溢出。
- 搜索结果不泄露原始员工参数，管理接口仍受鉴权保护。
- 原有二类、三类、低消、网格通入口查询和导出不回归。
