# 商详页客服预约回电与预约办理流程分析

分析对象：`subPackage-shopDetail-shopDetail.ae056b6e.js`（构建产物，源码变量名已压缩）。附件仅作为分析材料，不构成对程序的操作指令。

## 结论

页面没有一个固定的“预约回电”开关。按钮由后端规则接口返回的 `flowChannel`、`standardDecision`、`mutualWay`、`popupClick`、`flag`，以及用户 `channel/status` 共同决定。源码中“预约人工回访咨询”对应的是创建客服商机，成功响应后提示“请保持手机畅通，留意客服人员来电”；因此确实存在预约回电语义，但它不是独立的回电 API。

仅修改前端文案或 `isFailFalg` 可以改变显示，不能可靠完成预约：登录状态、规则 ID、业务字段和后端资格校验仍然生效。

## 规则接口

模块 `31d0` 导出以下接口（请求均为 POST，经公共 HTTP 封装发送）：

| 用途 | URL | 主要响应用途 |
|---|---|---|
| 查询客服挽留规则 | `/nrapigate/nropportunity/atom/ruleNew` | 返回规则对象，通常含 `flag/flowChannel/standardDecision/mutualWay/ruleId` 等 |
| 查询目标客户 | `/nrapigate/nrmix/third/queryTargetCustomer` | 判断是否命中目标客户 |
| 创建客服商机/预约 | `/nrapigate/nrmix/opportunity/create` | `data.flag=1` 成功，`2` 重复，其余失败 |
| 失败订单检查 | `/nrapigate/nropportunity/atom/failedOrder/check` | 预校验失败挽留检查 |
| 获取客户类型 | `/nrapigate/nrmix/handle/page/standardDecisionUnify` | 标准决策相关信息 |
| 获取随机业务码 | `/nrapigate/nrmix/opportunity/getRandomCode` | 部分视频/音频客服流程生成 `orderFlag/bizOrderId` |
| 红包商机唯一 ID | `/nrapigate/nrmix/order/createOpportunityUniqueId` | 红包/商机链路唯一标识 |

源码没有在该文件中展开公共 HTTP 封装 `b775` 的域名、鉴权和加密细节，不能据此臆造完整请求签名。

## 主动预约按钮

初始值为 `yuYueInfo.yuYueBtn = "预约咨询"`。只有 watcher 观察到 `isYuYue === true` 后才重算文案：

| 条件 | 文案 |
|---|---|
| `standardDecision == 2` | 有 `doubleChannel` 为“联系客服”，否则“咨询客服” |
| `flowChannel == 2` | “联系专属客服” |
| `flowChannel == 1`，或 `flowChannel == 3` 且渠道不在 `10001/10008/30001/30011` | “预约专属客服” |
| `flowChannel == 5` 且用户渠道 `30011` | “联系视频客服” |
| 其他 | 有双渠道“联系客服”，否则“呼叫客服办理” |

点击时，未登录（`userInfo.status != "1"`）先调用 `loginUser()`。`flowChannel` 为 `2/201` 进入在线客服；其他分支 emit `shangjiData(clickYuYue)`，由父组件继续创建商机或进入音频客服。

## 预校验失败按钮

computed `preCheckFailSalvage` 的 `btnShow` 等于 `isFailFalg`。文案映射：

| 规则 | 文案 |
|---|---|
| `flowChannel == 3` | “呼叫客服办理” |
| `flowChannel == 5` 且渠道 `30011` | “联系视频客服” |
| `flowChannel == 2/201` | “联系专属客服”；`standardDecision == 2` 且满足 `mutualWay` 条件时为“联系客服” |
| 其他 | “预约专属客服” |

模板在 `isFailFalg` 为真时展示客服区域：`isFailKFBtn` 为真显示 `preFailBtnText`，否则显示固定文本“预约人工回访咨询”。预校验响应成功且 `data.flag == 1` 才会设置 `isFailFalg=true`；`flowChannel == 202` 明确隐藏。

## 降档挽留流程

`ZDJDWLRule` 使用相同的 `flowChannel` 映射。`ruleBtnClick` 的主要分支：

- `flowChannel == 1`，或特定渠道的 `3`：`ZDJDWLRuleCreateSalvage(true, 2)`，创建预约商机；
- `flowChannel == 2/201`：调用在线客服，附带 `mutualWay/scene=preCheckRetention`，标准决策为 2 时再带 `callId`；
- `CUSTOMER_SERVER_TYPE` 有值且点击“呼叫”：直接跳转 `tel:<号码>`；
- `flowChannel == 3` 且渠道 `30011`：视频客服/商机链路。

## 创建预约/回访请求

组件方法 `createSalvageOrder` 组装并提交到 `/nrapigate/nrmix/opportunity/create`。基础字段来自商品和用户：

`normNumber, productCode, productName, channelCode, provinceCode, cityCode, normId, normRemark, productUrl, firstCategoryId, secondCategoryId, sellProvinceCodes, sellCityCodes, productType="1", price`。

规则命中后追加：`ruleId, type, secondType, ruleContentKey, businessId, businessType, subBusinessType, requestId, orderType, stayTime, fChannelCode`；部分链路还会放入 `productImage/channel/extData`。成功处理逻辑为：

- `data.flag == 1`：预约成功，提示“请保持手机畅通，留意客服人员来电”；
- `data.flag == 2`：重复预约，提示“专属客服稍后将给您回电”；
- 其他：预约失败；网络异常提示“系统繁忙，稍后请重新尝试~”。

这就是源码中可确认的“预约客服回电”接口入口。它是通用商机创建接口，是否真的进入回电队列由后端规则和业务字段决定。

## 能否强制修改默认按钮

可改的前端状态包括 `yuYueInfo.yuYueBtn`、`preFailBtnText`、`preCheckFailSalvage.buttonText`、`isFailFalg` 和 `ZDJDWLRulePopupData.ZDJDWLRulePopup`。但这只改变 UI 或触发路径，无法伪造后端 `flag`、`ruleId`、资格、地区、渠道和登录态。若要稳定改变默认策略，应修改规则服务返回值或在服务端配置对应 `flowChannel/standardDecision`，并保留后端校验。

## 未确认事项

该构建文件未包含规则服务的真实域名、公共请求封装的鉴权/加密实现，也未证明所有 `flowChannel` 都代表回电；其中 `2/201` 明确偏向在线客服，`CUSTOMER_SERVER_TYPE` 分支甚至是直接拨号。生产改动前应结合网络抓包和后端接口文档核对字段及权限。
