# AI豆倍享合约下线判断与本地在售模拟

## 源码结论

当前捕获版本的 `/bounsPoints` 路由和业务组件仍存在，统一订购参数也仍保留：

- `packageId=2840305334`
- `packageCode=JFBXHY`
- `productShowCode=G_JFBXHY`
- `pitemShowCode=XY` 或 `BXY`

该版本不是通过 `showBounsPoins` 的实时响应判断下线。虽然公共 API 对象仍声明了 `/portal-bff/api/bounsPoints/v1.0/showBounsPoins`，业务组件没有调用它；组件挂载时只记录“状态校验跳过”。实际隐藏页面的直接条件是业务组件根容器中的 `display: none`。

全局响应拦截器仍会把 `portalGlobalErr`、`terminalErr` 等运营商错误码跳转到统一错误页，但这是通用接口错误处理，不是本次业务组件中的产品在售判断。

## 本地模拟改动

本目录基于原 ZIP 创建，未修改原始 HAR 和 ZIP：

1. 将业务组件根容器从 `display: none` 改为 `display: block`。
2. 将 `/bounsPoints` 路由的登录和渠道来源要求关闭，仅用于本地渲染。
3. 将确认办理替换为本地延时和模拟成功消息，不调用统一订购函数。
4. 本地服务器阻断所有 `/nwt/portal-bff/` 和 `/nwt/sso/` 请求，并通过 CSP 禁止连接外部域名。

本地页面只能证明原业务内容和交互仍可渲染，不能改变运营商后台商品目录、资格校验、短信模板或统一订购接口的受理结果。

## 启动

```bash
node server.mjs
```

默认地址：`http://127.0.0.1:8896/nwt/portal/bounsPoints`
