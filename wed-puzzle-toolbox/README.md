# 周三拼图互助工具箱

独立 Web 工具：手机号验证码登录 / App CK 导入、一键导入有权限的 cookie-app 账号、三档库存、批量互赠、号池接力、逐条接收、达标抽图和每日任务。

## 启动

需要 Node.js 20 或更新版本。

```bash
cd /Users/ZevinGunn/CMCC-PROJECT/wed-puzzle-toolbox
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:4186`。开发模式 `npm run dev`，前端 `4187`、API `4186`。
后端只监听本机回环地址，根路径自动进入 `/wed-puzzle/`。可通过 `PORT` 更改生产端口，`WED_DATA_DIR` 更改账号库位置。

## 公网部署

入口：`https://home.1008086.xyz/wed-puzzle/`。Nginx 将这个前缀（不去除路径）代理到 `http://127.0.0.1:4186`，并固定 `Host: home.1008086.xyz`。部署配置见 `_部署方案/cmcc.nginx.conf` 的 home 段。

```bash
pm2 start ecosystem.config.cjs --only wed-puzzle-toolbox
pm2 save
sudo /opt/homebrew/bin/nginx -t
sudo /opt/homebrew/bin/nginx -s reload
```

- `WED_PUBLIC_ORIGIN=https://home.1008086.xyz` 启用该域名；默认不接受公网 Host。只允许指定的同源请求，API 要求 `X-Wed-Toolbox: 1`；这个请求标记不能代替登录。
- `WED_AUTH_ORIGIN` 默认 `http://127.0.0.1:3101`，服务端仅转发 `admin_session` / `user_session`，通过只读 `/api/admin/me` / `/api/auth/me` 校验身份，导入时调用本机受限凭据通道。管理员可使用，普通用户需要 `benefitActivity`（权益活动）权限；登录服务故障拒绝访问。
- 每个登录身份的账号库独立保存在 `data/owners/<身份哈希>/`。原本机账号库保留在 `data/`，公网不会读取它。CK、活动 Token 和任务检查点继续加密存储；不向前端返回凭证。
- 所有身份共用同一个串行执行锁；其他用户的操作进行中时，请等待。后台任务每次调用活动接口前重新核对原登录会话与权限，过期或撤权会暂停，不自动重试提交。
- 未登录页面提供站点登录入口。登录后返回工具箱点击“重新检查”。无需对外开放 4186 端口。
- PM2 配置的解释器需要 Node 20+；更换环境时使用 `WED_NODE=/实际/node路径 pm2 start ecosystem.config.cjs`。

## 凭证

- **一键导入 cookie-app**：在 home 站点登录后点击工具箱顶部“一键导入 cookie-app”。普通用户仅导入自己名下号码，管理员可导入其管理范围内账号；普通用户仍需权益活动权限。筛掉已停用、明确失效/过期或缺少 CK 的账号，再按顺序置换活动会话、核验手机号和查询三档拼图。不能登录活动的号码单独报失败，同手机号更新既有记录，不重复累计库存。
- 导入共用全局串行锁，后台处理并展示进度及逐号结果，关闭弹窗不终止导入；服务重启标记中断且保留已导入账号。号码池最多 100 个，超出的新增号码会报失败。导入仅登录/查询，不自动执行任务、转赠、抽图或领券。
- 服务端通过 `WED_AUTH_ORIGIN` 的本机 `/api/wed-puzzle/toolbox/accounts` 和 `/accounts/:id/session` 读取有权限的凭据。通道要求真实站点会话、身份一致、直接回环地址、回环 Host 且无代理头；公网拒绝调用。凭据只在后端传递并进入工具箱加密库，前端只收到脱敏结果。无站点会话的本机模式需改用 home 公网登录入口后导入。

- **短信登录**：复用 `wx.10086.cn/website/bind` 的网页登录和 AES 加密协议，再准备周三活动会话。不是原生 App `x-qen=14` 登录。
- **活动 CK**：导入活动页面的完整 Cookie，必须能建立 `HLWHD_SESSION_TOKEN`。
- **App Token**：支持下面的 JSON 格式，或 `{ "postBody": { ...实际 appTokenLogin 入参 }, "sid": "..." }`。使用实际账号/客户端参数，不使用 HAR 里的其他人凭证。

```json
{
  "token": "实际 App Token",
  "sid": "同一次活动登录的 sid",
  "cookie": "可选 Cookie",
  "provinceCode": "实际省份编码",
  "cityCode": "实际城市编码",
  "userCheckId": "实际客户端字段",
  "carrierOperator": "002",
  "appVersionCode": "实际 App 版本"
}
```

也可以提供官方 `loginUrl/activityUrl` 以提取 sid。**原生 App 的 JSESSIONID 单独不是活动登录凭证，不能转换成原生 Token**；不猜测其签名/加密，不将 Cookie 字符串直接当 Token。

登录后调用 `GET /hlwyxhdhub/api/wedrecharge/_pub/rec_login` 校验身份，再查询所有档位。已有样例返回 `phone: 138****1234` 和 `mobileCode`：导入需填写完整手机号，校验可见前三位/后四位并以活动 `mobileCode` 指纹去重。中间四位无法由脱敏响应验证，应准确填写；短信登录的完整手机号来自实际认证请求。重复号码更新原记录，不重复计入库存。

## 互赠和抽图

1. 添加参与号码，查询 95 折（4 图）、9 折（6 图）、8 折（9 图）的库存。
2. 选择接收号码后默认勾选其他号码，可调整赠送方；选择起始档位和模式。
3. “全部余图”固定本次选中号码/档位的可转数量，逐张转出，每种保留最后一张。“按缺口补齐到 11 张”根据当前库存和号码池可转数量计算缺口，优先补齐其他图；不写死稀缺编号，也不把新抽到的图加入原赠送清单。
4. 预览后确认执行。每次查赠送资格 → 生成一个转赠 Token → 接收号码调用领取 → 核验赠送方 -1 和接收方 +1 → 下一张。
5. 完成本档计划转赠后，勾选自动抽图时，必须**恰好一张拼图库存为 0，其他每种大于 10，即至少 11 张**，且官方 `DrawStatus=1`、次数大于 0、前一档资格满足，才抽一次。如果转赠已直接补齐全部拼图，则不消耗抽图次数。
6. 缺图由该号码实时库存确定，不存在工具预设的固定稀缺编号。全都拥有或者缺两张以上时，不使用此抽图策略。满库存出缺图是用户提供的经验规则，源码没有服务端保底证明；抽后必须核验实际缺图 +1、次数 -1。未抽中缺图暂停，同一任务该档不再抽第二次。
7. 默认启用“自动完成后续档位”：从选定起始档按 95 折 → 9 折 → 8 折串行完成，跳过已完成/已领券档。下一档重新查询所有赠送方库存并固定新的可转余量，最多每档抽一次，共三次。需要领券解锁时，只在前一档集齐且官方 `Status=2` 时领取前一档券；已在确认弹窗中告知此操作。最后一档券不自动领取，仍可手工领取。库存不足、次数不足、官方未开放或解锁失败时暂停，不越级。

接收号码已经满足条件时，可使用“达标抽一次”，不必再次选择赠送号码。此入口同样在提交前核对只缺一张、其他每种至少 11 张和官方资格。

可将多个官方 `giveCard` 分享链接每行一条粘贴到“接收外部链接”。只解析 Token，不在赠送方会话或普通浏览器中随意打开链接；使用选中接收号码的活动会话串行领取。重复链接去重。

## 号池接力

在“号池接力”中选择参与号池及其中的目标号码、起始/目标档位，可指定一个优先接收号码。点击“核对接力库存”查看逐号方案，再确认执行。

- 每种拼图的余量单独计算：库存减一，并核对官方 `tradeList` 的数量和 `btnStatus=2`。查询失败或转赠资格查询失败的号码不贡献旧缓存库存；站点撤权立即中断。
- 所有缺图都有可赠余量时，只转赠补齐缺图，不搬运无必要的普通图、不消耗抽图次数。若仅一种缺图没有可赠余量，必须其他每种都能够补至 11 张且官方允许抽图，才规划本档转赠和一次抽图。多个缺图无法补齐、次数不足或普通图余量不足时，不先搬运一个无法完成的方案。
- 按目标选择顺序处理，优先号码在前；目标从起始档逐档完成。条件不足的目标先等待，其他可行目标完成后重新评估。完成号码仍保留每种一张，其余库存继续贡献给后续目标。必要时领取前一档券以解锁，最后一档券不自动领取。
- 预览是同一库存快照下的逐号评估，多个目标共享余量，不能将预览中可行号码数当作保证可完成数量。每档结束后重新查询全池并重算；全部目标无可行方案时暂停，日志逐号列出缺口。补充本次号池库存或次数后可以继续。
- 队列固定本次号池、目标及档位范围。后来添加的号码不会自动加入；需要结束旧队列，重新选择和预览。执行前再次校验预览版本，库存/资格变化则要求重新预览。
- 抽图去重按“号码 + 档位”保存，同一队列同一号码同一档位最多一次。未抽到缺图立即暂停，恢复不会自动重抽；结果不明时保存原检查点，仅核验结果。领取和抽图均复用既有串行、逐张库存核验与重启恢复机制。
- 接力会给每个完成号码留下各一种拼图，池内余量有限，不能无限接力；新抽到的缺图只有一张时无法再次转赠。“普通图达标必出缺图”仍是经验策略，并非已验证的服务端保底承诺。

## 每日任务

支持“一键完成全部号码”、完成当前号码、执行勾选号码、执行单个任务。查询号码和勾选执行范围独立；未勾选号码也可以执行当前号码或全部号码。按接口最新 `taskList`、`status=0` 和顺序处理，不写死任务名称或 ID：

| taskType | 调用流程 |
| --- | --- |
| 1、6 | `finishTask(taskId)` |
| 2（邀请）、3（充值）、5（App 浏览） | 按用户要求尝试 `finishTask`，不虚构助力/充值/原生浏览成功 |
| 4（插件浏览） | `getJtToken` → `getOneTaskInfo` → `openFinish(cToken)`；默认快速模式不加本地等待，关闭快速模式时等待服务端 `scanTime` |
| 未知类型 | 记录跳过 |

快速模式属于项目执行策略，与官方类型 4 前端倒计时流程不同；上游可能因时间或资格不满足而拒绝，此时记录真实错误，不虚报成功。

每个提交后再次查询任务列表和抽图次数。只有明确完成文案、完成次数增加/达到目标或抽图次数增加，才认定完成。确认进度增加且任务仍为可执行、还有额度时，继续下一次，最多每任务 100 次；不复用旧状态盲目上报。非零状态也可能表示未开放，不能一概标为“已完成”。接口明确拒绝时记录失败并继续其他任务。接口明确接受但复查进度未更新时，记入“上报未确认”，不计为完成、不重复该项，继续其余任务。提交响应丢失/网络中断时保留检查点并暂停，继续只核验原操作，不重复提交。活动凭证失效的号码单独记录并跳过。没有伪造真实充值或助力步骤。

## 串行与恢复

- 一个全局队列；互赠、接收、每日任务、查询和登录不会同时进行。最多 100 个账号，单个外部接收任务最多 500 条链接。
- `data/state.enc` 为 AES-256-GCM 加密账号库与操作日志，`data/key` 是随机密钥（权限 0600）。**备份/迁移必须同时保留这两个文件**，密钥丢失不可解密；重启不得自动重放写操作。
- `data/process.lock` 防止两个进程同时操作同一账号库。
- 转赠 Token、抽图、领券、任务提交前持久化检查点。领取失败保留原 Token，可复制原分享链接；不重新生成。生成 Token 的结果不明且没有 Token 时须核对官方记录，不能安全重新生成。
- 暂停会等待当前请求结束；已生成转赠尽量完成领取并核验。重启后自动暂停，点击继续先核对检查点。
- 抽图/领券/任务提交响应丢失时，不重复写入；依据库存/次数/状态核验。结果仍未知时保持暂停，可核对后结束任务。
- 本机页面 API 校验 Host、Origin 和工具请求标记，阻止跨站请求；Cookie/验证码不写浏览器持久化存储、不进入日志。
- 数据目录和依赖/build 文件已被 Git 忽略。代码可以提交，账号库不可提交。
