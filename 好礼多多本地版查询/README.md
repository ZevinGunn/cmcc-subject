# 北京移动消费与二类合约查询

由两个独立页面和对应 Node.js 代理组成：一套用于 ARPU 消费查询与测算，一套用于本地二类合约资料检索。

## 已实现功能

### ARPU 消费查询

- 输入号码并通过本地代理查询北京移动相关消费信息。
- 导入号码并维护待查询列表，展示查询结果。
- 使用消费计算器辅助测算。
- 提供合约查询入口、页面图标和 `/api/health` 健康检查。

### 二类合约资料检索

- 页面内置合约目录，不依赖每次向上游查询合约清单。
- 按关键词、类别、编码前缀、长期有效状态和资料完整性筛选。
- 展示已有的方案编码、名称、资费、期限及生效/失效时间等资料。

合约检索是静态资料查询，不是账号资格核验或订购服务。更完整的二类、三类和低消等级统一检索见工作区的 `contract3-query/` 项目。

## 启动

代理使用 Node.js 内置模块，没有单独的 npm 依赖安装步骤。在项目目录分别运行：

```bash
# ARPU 查询：3000 端口
node proxy-server.js
```

```bash
# 二类合约查询：3001 端口
node proxy-server2.js
```

页面地址：

- `http://127.0.0.1:3000/arpu.html`
- `http://127.0.0.1:3001/productSearch.html`

macOS 可执行 `zsh run.sh` 同时启动两套服务并打开页面；`start.command` 用于启动 ARPU 查询。当前代理端口在源码中分别固定为 3000 和 3001。

## 主要文件

| 路径 | 作用 |
| --- | --- |
| `arpu.html` | 消费查询、号码队列与计算器 |
| `productSearch.html` | 内置合约数据和筛选页面 |
| `proxy-server.js` | ARPU 页面、上游代理和健康检查 |
| `proxy-server2.js` | 合约页面与对应代理 |
| `run.sh`、`start.command` | macOS 本地启动入口 |
| `logs/` | 运行日志，保留本地，不随源码提交 |

## 运行说明

静态合约检索可以独立使用；消费查询是否返回有效结果仍取决于上游接口、网络与会话要求。代理当前未指定回环监听地址，也未提供管理员认证，启动时应使用可信的本地网络环境，不将原型直接当作开放查询服务。

电话日志、接口响应存档和账号数据不属于可分享源码。本文未执行真实号码查询，也未更新内置合约资料。
