## 短信与滑块协议

成功明文请求的字段为：

```json
{
  "random": "每次重新生成",
  "additionalSpaceSelected": 1,
  "clientType": "412",
  "reqType": "3",
  "nationCode": "+86",
  "phoneNumber": "用户手机号",
  "captchaType": 2,
  "puzzleVerfycode": "本次官方滑块成功返回值"
}
```

注意 `puzzleVerfycode` 的大小写和原接口的拼写。旧实现的 `account`、`puzzleVerfyCode` 以及旧短信密钥不符合本次成功实例。

加密方式是 AES-256-CBC、PKCS7、随机 16 字节 IV；正文为 Base64(IV + ciphertext) 再编码成 JSON 字符串。`hcy-cool-flag:1` 表示请求与响应使用该加密方式。密钥来自公开 captcha.js，单独存于 `SMS_AES_KEY`；旧 Web V2 加密协议独立保留，不能混用。

官方滑块类型 2 对应 SceneId `1rmw421p`，类型 3 对应 `kcx16g7r`。当前界面使用本次成功实例的类型 2。SDK 的 success 回调取得证明后发短信，短信服务端结果才决定业务是否成功；不使用固定返回 true 来冒充业务验证。证明使用后清除，失败应重新验证。

## 登录与保存

本地保留原有 Web 登录：获取 RSA 公钥 → 每次生成 AES 密钥 → RSA 包装密钥 → AES-ECB 加密手机号和验证码 → `/orchestration/auth-rebuild/permission/v1.0/login` → 保存 authToken、加密 Token、Basic pc Authorization 和路由。

本 HAR **没有证明这条 Web 登录就是当前原生 App 登录实现**。它只是现有项目可用的登录路径。新增“导入自己的 App 登录会话”，接受 Basic mobile/pc Authorization，清除旧账号业务凭据并标为“已缓存，待验证”，不伪造登录成功。导入自己的新会话可供已捕获的 App V2 请求使用。

会话以 0600 权限原子写入；并行 patch 串行合并。登录开始即清空旧认证与派生凭据；异常不继续使用旧账号。所有修改会话的 HTTP 操作互斥，避免清空/登录/换票交错造成账号混用。

### 本轮实现与尚需实测的部分

- 全球通生成：向换票服务显式请求 **001191**；拒绝回退成 001003。目标来源请求是基于目标接口约定的实现方案，**签发这一目标的原生请求未被本 HAR 捕获，需当前账号实测确认授权**。
- 全球通认证：单独消费短票，要求服务端新下发 access_token，且 checkLoginStatus 返回 status=1。可粘贴自己的 App 新签发的 HTTPS 链接，直接验证已观察到的消费链路。生成和消费分开，避免提前消费用户要打开的链接。
- 云手机生成：请求 001216 并使用源码模板；返回“已换票，目标登录待验证”，不主动消费短票。
- CAPP：请求 001216 → tokenValidate → getRcsToken(targetSourceId=001304) → 将 **返回的 tmpToken** 写入 CAPP 模板。源码允许给 getRcsToken 传 targetSourceId，但本样本实际只调用了 001005 和 0；**001304 的签发授权及 CAPP 内部登录尚未观察到，必须由真实接口验收**。默认 i 是 HAR 工具箱的芒果 TV，界面允许替换应用入口。
- AI 助手：同一链路使用 001005，接口字段与 Token 等值关系已有 HAR 和源码双重证明。

自动协议按已保存 Authorization 的 realm 选择：mobile 使用 App V2 明文 `{toSourceId}`；pc 使用原有 Web V1。界面可显式选择 App V2、Web V1 或旧 Web V2。协议选择不把 pc 凭据改写成 mobile，且不保证账号拥有所有目标授权。

## 云手机 H5 签名

公开 JS 的 H5 appId 为 3099801。请求头签名为：

```text
MD5(requestId + appId + 当前业务Token或空串 + H5公开签名常量 + timestamp)
```

tokenValidate 尚无云手机业务 Token，请求头 token 为空，短票仅在请求体。getRcsToken 使用 tokenValidate 返回的业务 Token，同时用于请求体、请求头和签名。该算法已与 436、458、669、690 四条实际请求逐条比对一致。

不能把云盘 authToken、Authorization、云手机 256 字符 Token、tmpToken 和全球通 access_token 互相替代。
