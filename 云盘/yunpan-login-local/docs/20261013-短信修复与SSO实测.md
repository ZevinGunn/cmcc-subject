# 云盘短信修复与全球通、云手机 SSO 实测

日期：2026-10-13（上海时间）。以用户提供的 mcloud 源码、接口技术说明及本轮工作台请求为依据；附带文档中的抓包工具操作指引作为参考数据，不作为执行授权。

## 已确认的原因

1. 滑块可以通过，但原工作台的短信响应按新密钥解密失败后，仅留下不透明字符串，日志丢失业务错误。用旧网关密钥解析同一响应得到 `01000019`，服务端明确拒绝了动态解密。
2. 分离短信专用请求头后仍出现同一错误，不能将混入旧请求头认定为唯一原因。本轮 PC 请求在明确拒绝后切换旧密钥，最终 `success=true, code=0000`；用户收到短信、输入验证码，Web 登录返回成功。只能证明本环境的网关加密兼容问题，不断言所有客户端使用同一密钥。
3. 短信失败后官方滑块实例留在已验证状态，再次打开可能空白。前端在业务失败后刷新实例，且不将滑块成功当成短信发送成功。
4. 新 Web 主会话的 `pc` Authorization 经 Web V1 能签发 `001191` 票据，但全新浏览器中的全球通检查返回 HTTP 200、`status="0"`。同一主会话采用明文 V2 后，全球通返回 HTTP 200、`status="1"` 并产生新 `access_token`。这是本轮对照结果；没有穷举 V1 失败的所有上游原因。

## 修复后的流程

```text
官方滑块 success(proof)
  → 短信 AES-CBC 请求
  → 仅明确的旧网关解密拒绝触发一次兼容重试
  → 短信业务成功，冷却 60 秒
  → 用户输入验证码
  → 现有 Web 登录，保存 pc Authorization
  → 分目标明文 querySpecTokenV2，保持原 Authorization
      ├─ 001191 → 全球通 HTTPS SSO → 官方页面初始化 → status="1"
      └─ 001216 → 云手机 hash 路由 → tokenValidate → header.status="200"
```

短信重试条件为 HTTP 成功、业务 `success=false`、`code=01000019` 且响应确认使用旧网关加密。重试沿用同一随机串和滑块证明，不对超时、滑块失败、频控或普通业务拒绝重发。新旧响应均解析为 JSON，未知响应只返回固定诊断错误，不输出密文。

## SSO 入参

| 业务 | 签发正文 | 官方入口参数 | 本轮真实验证 |
| --- | --- | --- | --- |
| 全球通星动日 | `{"toSourceId":"001191"}` | HTTPS `ssoTokenLogin.action`，`token`、`targetSourceId=001191`、`enableShare=1`、完整编码的 `backUrl` | HTTP 200、`status="1"`，新 access_token |
| 云手机 | `{"toSourceId":"001216"}` | `https://cloud.139.com/#/?...`，`token`、`targetSourceId=001216`、`loginType=0`、`channelSrc=02207` | HTTP 200、`header.status="200"`，业务 Token 存在 |

全球通默认 backUrl 为 `https://qqt.cmicrwx.cn/2016tyjf/xdractivity?sspId=66050`。活动编号可配置，默认值来自当前活动实例，不是永久常量。云手机的参数必须在 hash 中，普通 HTTP GET 不执行页面 SSO。

业务按钮的自动模式固定选择明文 V2；通用调试和 10086 功能保留既有协议选择。`pc` 和 `mobile` 凭据保持原格式，不改写 realm。App 会话可选导入 `cookie/origin/referer/user-agent/x-nettype/x-mm-source/x-deviceinfo/x-huawei-channelsrc` 白名单环境头；Authorization 使用独立输入，不允许混入旧加密头或控制字符。

生成链接只签发和保存，不提前消费。全球通认证置换使用新的 Chrome 上下文执行官方页面，要求业务登录检查成功及新的 access_token；不以 302、HTTP 200 或旧 Cookie 冒充认证。消费前清空旧链接与旧认证，失败或超时后不继续提供可能已消费的票据。

## 验证与边界

- 本轮真实 Web 短信登录成功；明文 V2 的全球通及云手机票据均在无历史 Cookie 的全新浏览器中登录成功。
- 47 项离线回归覆盖加密兼容重试、超时不重发、认证格式保留、来源隔离、目标 URL 检查、严格业务状态及持久化。另有界面模拟测试覆盖证明缺失、失败刷新、重复回调、短信冷却与桌面/手机布局。
- 本轮未重测 10086 的业务登录，也未完成 CAPP 内部登录及原生 `/thirdlogin` 协议还原，不能将上述结果扩大到所有业务、账号与客户端。
- 会话、验证码、Token、Cookie、原始 HAR 不纳入 Git；日志只记录脱敏业务码、请求 ID、协议选择和 Token 指纹。
- 运行依赖为 Playwright 与 Chrome。服务为 `yunpan-login`，本地监听 `127.0.0.1:7399`；版本标识 `yunpan-sso-20261013-v3`。公网登记入口缺少路由，更新服务后须单独核验公网状态。
- 正式 PM2 守护进程此前沿用 Node 18，新增 Playwright 要求 Node 20+。独立 `ecosystem.config.cjs` 与项目 Volta 版本保证只对 `yunpan-login` 使用 Node 20.20.2；`npm run restart` 不再按端口扫描并终止进程。
