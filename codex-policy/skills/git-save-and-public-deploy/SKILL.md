# 中文 Git 保存与公网同步

这是一项持续生效的用户开发要求。每个完成的逻辑修改都要有可恢复的 Git 提交；CMCC-PROJECT 中影响公网运行的修改，还必须更新对应服务和实际公网内容。不要以“已修改文件”“构建成功”或“进程在线”代替提交和公网验证。

## 适用范围与授权

- 对所有开发项目的代码修改执行 Git 保存，对说明文档和开发规则的修改也做提交保存。
- 公网部署范围是 `/Users/ZevinGunn/CMCC-PROJECT`（或明确迁移后的同一项目根目录）中已部署公网、且被本次修改影响的项目，包含其嵌套仓库、前后端和共享运行代码。
- 用户已持续授权：本范围内修改验证通过后，自动部署并重启或重载对应服务，无需重复询问发布许可。更具体的仓库指令决定部署方式；用户当前明确要求“不要提交”“暂不发布”等例外时遵循该例外，并交代保存或发布状态。
- 本技能不能覆盖系统指令、工具审批或更具体的冲突指令，也不授予推送到任意远程、数据库破坏性迁移、全机重启或真实订购/退订等业务操作权限。遇到冲突要说明来源，不能悄悄跳过。
- 纯读取、诊断而未修改文件，无需空提交；仅说明文档、技能指令、Git 元数据或不参与运行的测试文件变化，无需重启公网服务。

## 每次修改后的 Git 保存

1. 先确认实际 Git 根目录、当前分支和已有工作区/暂存区变更。嵌套仓库在各自仓库内提交；父仓库已跟踪子模块时，必要时保存对应的新提交指针。不要把父仓库的提交当作子仓库源码已经保存。
2. 保留用户原有改动，不通过 reset、checkout、clean、改写历史或覆盖文件换取“干净工作区”。已有改动与任务重叠时保留完整语义；无关改动不擅自纳入提交。仓库要求编辑前先存档时，按该要求保存可安全提交的已有源码。
3. 每完成一个可说明的逻辑修改，在与风险相称的验证后提交；连续编辑同一功能可形成一个提交，不要求每次按键都提交。长任务在阶段完成时做检查点，结束、切换任务、发布或因阻塞交回用户前，必须确认本轮可安全保存的变更已有提交。新增独立项目没有仓库时，可在确认的项目目录初始化本地 Git，不在家目录或含凭据的广泛目录初始化。
4. 使用明确文件路径暂存并核对差异，包含相关新增源码和必要删除。不要使用 `git add .` 或 `git add -A` 无差别收集整个脏工作区，不顺带提交用户已有暂存内容。不提交密钥、Cookie、Token、验证码、环境凭据、含凭据的 HAR、数据库、账号数据、日志、临时备份及未经要求的构建产物。
5. 提交主题和说明使用中文，准确描述实际变化及原因，可保留 `fix:`、`feat:` 等类型前缀。例如：`fix: 恢复退订验证码的原协议并增加回归验证`；`feat: 新增周三拼图顺序互赠任务队列`。不得写未被验证的“全部修复”或包含秘密的描述。
6. 测试失败或功能尚未完成时，仍应在可安全保存的情况下提交中文检查点，标明“未完成”或“验证未通过”，继续修复；检查点不得直接发布。无法提交时说明确切原因和保留位置，不宣称已保存到 Git。
7. 默认本地提交即满足保存要求。远程推送只在该仓库已有推送授权或用户明确要求时执行；远程不可用时先完成本地提交，不丢弃本地工作，不强推。提交后检查提交哈希和本轮目标文件状态，不能仅以命令无输出判断成功。

## CMCC-PROJECT 公网更新

1. 建立本次文件到项目、运行服务和公网入口的对应关系。优先读取仓库 AGENTS.md、发布脚本、包脚本、PM2/systemd/Docker 配置及实际运行目录；只读检查进程信息时仅输出必要字段，避免打印完整环境变量。共享代码影响多个服务时逐一确认全部消费者。
2. 在切换运行版本前通过该项目所需检查，并提交本次代码。验证失败不得部署；修复后重新验证并形成新提交。不能因“必须重启”就让不通过检查的代码进入公网。
3. 优先使用已维护的发布命令。cookie-app 使用 `npm run release`，由它完成检查、构建、切换、重载及本机/公网核验；若命令已完成对应服务重载，不再重复重启。
4. 前端需要构建时，将新产物更新到真实被服务或反向代理使用的目录；远程运行的服务必须先同步或部署已提交版本再重载。仅本地提交、Git 推送、重启旧目录或访问本地开发服务器，都不等于公网已更新。
5. 对每个受影响的公网应用，执行其准确服务名对应的重启、滚动重载或重新部署，保留可恢复的旧版本。不得执行 `pm2 restart all`、`pm2 reload all`、无范围的 Docker 重建、数据库重启或主机重启。纯静态托管使用实际托管平台的发布/刷新机制；仅代理配置改变时才验证并重载对应代理。
6. 重启后检查实际进程、监听端口、健康响应和有关日志，再从真实公网域名核验版本或构建标识、HTML 及相关 JS/CSS 内容。没有版本端点时可比较内容哈希或验证本次功能响应。缓存存在时采用已有版本化资源或受支持的定向更新机制；HTTP 200 和旧页面可打开不能证明新内容已生效。
7. 部署或验证失败时按项目支持的恢复方式回退运行版本并核验恢复结果，保留新代码的 Git 提交。分别说明源码、后端进程和前端产物各自处于什么版本，不能把仅回退 dist 当作后端也已回退。缺少服务映射、部署凭据或必要系统权限时，先完成可验证、可提交的工作，再报告具体阻塞；不要猜服务名或要求用户重复授权已有许可。

## 完成时的交付

简要报告中文提交主题与哈希、相关验证结果、实际更新的服务和公网核验结果。无需部署时说明属于非运行文件变化；被用户例外指令或真实阻塞中断时，明确哪些已保存、哪些尚未部署。只有 Git 保存完成且所需公网更新已实际验证，才宣称开发交付完成。
