# 本地快捷登录与官网动态会话

## 用户流程

在本应用添加手机号、输入服务密码并点击「快捷登录」。不打开可视浏览器，不跳转官网，也不要求用户在官方页面手动登录。服务密码不落盘；每个账号独立保存会话。

## 为什么后台仍需要本地引擎

官网的普通 HTTP 访问会返回 412 动态校验页。提供的页面资源和 HAR 显示，业务 JSON 之外还有动态 URL 参数、请求头及改写后的请求体，不能将 HAR 中的一次性风控参数作为常量重放。

因此「无需跳转浏览器」通过本地无头 Chromium 完成：后台加载官网会话，执行当前版本动态脚本，再由同源 XMLHttpRequest 提交业务请求。认证仍需联网，此功能不是离线认证，也不是脱离浏览器引擎的纯 HTTP 实现。

原先 Chromium 配 Safari UA 的配置在联机检查中出现空白 400。当前采用与已安装 Chromium 主版本一致的 Chrome UA，并保持无头运行；匿名 qryLoginAccno 已实测返回 200 及可解码的业务结果。这只证明匿名会话初始化，不能代替真实账号成功登录验证。

## 认证结果

1. 先通过 qryLoginAccno 确认已到达业务接口，初始化失败不发送密码。
2. 以 3DES-CBC、PKCS7 填充加密服务密码，提交 passwordCheck。
3. 仅在业务码成功后，再查 qryLoginAccno，核对登录号码。
4. 同一账号的认证链路串行执行，其他账号独立运行。
5. 任一步失败均不认定登录成功；失败会话关闭并删除该账号 profile，以免旧登录态被复用。

不将风控动态参数、Cookie 值、上游 Token 或密码写入登录日志。诊断只保留状态码、路径、响应类型/长度和 Cookie 名称。

## 验证边界

新提供的 HAR 不含响应正文，不能单凭 HTTP 200 推断登录成功。页面资源可验证加密参数和业务请求字段；本地回归可验证提交、号码核对、错误处理及会话隔离。实号是否通过风控与服务密码验证仍需使用者输入当前有效密码，不承诺绕过验证码或其他额外认证要求。
