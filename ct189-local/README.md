# 北京电信本地账号工作台

在本机管理北京电信账号、无窗口服务密码登录、分组与批量任务。独立 Python 脚本支持青龙环境变量导入多个账号。

## 本地运行

```sh
pnpm install
pnpm --filter ct189-local-backend exec playwright install chromium
pnpm run dev
```

- 工作台：http://127.0.0.1:5711
- 本地 API：http://127.0.0.1:5710，仅监听本机。

## 账号管理

- 添加、编辑备注与分组、启用/停用、删除账号及本地会话。
- 号码/备注/分组搜索，登录状态与分组筛选。
- 多选批量检查登录、更新资料、关闭会话、分组、启停和删除。
- 批量导入：每行 `手机号#备注#分组`，不包含密码。每批最多 200 个；手机号重复时跳过，格式验证失败时整批拒绝。
- 任务记录保存最近 100 批，每个账号分别展示成功、失败、部分结果或跳过。任务串行执行，页面刷新后可继续查看；服务重启将未完成任务标记中断，不自动重放。
- 停用账号跳过登录检查和资料更新，仍可关闭会话。停用不等于清除 Cookie；删除账号会清除对应浏览器配置。任务执行或排队中禁止删除对应账号。

资料更新会先核验登录号码，再查询活动 310 和余额候选接口。官方返回的部分结果会保留并标注失败，不把 HTTP 200 当业务成功。详情中可展开最近原始查询结果；结果可能包含运营商返回的账号信息，请勿公开。

**当前新版界面不提供签到和领取按钮。** 这些操作需核实协议后另行接入，不混入批量资料更新。历史后端候选接口仍保留用于兼容，不作为已验证的产品能力。

## 本地快捷登录

添加手机号后，点击列表「登录」，输入数字服务密码。登录全程不打开浏览器窗口、不跳转官网。服务密码只用于当次加密提交，不保存到账号文件、日志或会话缓存；后续自动重新登录需再次提供密码。

后台以独立无头 Chromium 执行北京电信动态风控，向官方提交 3DES 加密密码。仅当提交成功且官网返回的号码与目标手机号完全一致时，才标记登录有效。匿名初始化最多尝试两次，密码请求不自动重放。官网风控、网络或人工验证仍可能导致失败；不会显示假成功，也没有跳转官网的回退流程。

`CT189_HEADLESS=false` 不启用可视窗口。账号启停和任务记录沿用旧账号文件兼容加载，无需重新建号。

## 青龙定时任务

脚本：[`qinglong/ct189.py`](qinglong/ct189.py)；安装及变量说明：[`qinglong/README.md`](qinglong/README.md)。

变量 `CT189_ACCOUNTS` 每行 `手机号#服务密码#备注`，也支持 JSON 数组。命令：

```sh
python3 ct189.py --tasks login
python3 ct189.py --tasks login,activity
```

`login` 检查会话并在需要时登录；`activity` 只读查询活动资格。网页和青龙各自保存会话，不需要常驻 Node 服务。签到、领取尚未接入，脚本预留任务注册入口。

## 数据与验证

- `backend/data/accounts.json`：账号、操作记录和批量任务；通过临时文件原子替换保存，权限 600。
- `backend/data/browser/<accountId>/`：隔离会话，包含 Cookie，勿提交或分享。
- `CT189_DATA_DIR` 可覆盖后端数据目录，测试使用临时目录。
- 青龙缓存独立存储，具体权限和锁机制见脚本文档。

```sh
pnpm test
pnpm build
# 前端启动后，使用模拟响应验证桌面/手机交互：
pnpm --filter ct189-local-frontend test:browser
# 安装 Python 依赖后：
cd qinglong
python3 -m unittest discover -s test -v
```

自动化测试不使用真实凭据、不联网领取权益。此项目当前为本地工作台，未配置公网部署入口。
