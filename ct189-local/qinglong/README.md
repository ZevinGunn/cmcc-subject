# 北京电信青龙脚本

`ct189.py` 是独立 Python 3.10+ 脚本，不依赖本地助手的 Node 后端。使用本机无头 Chromium 执行北京电信官网风控，直接向 `wapbj.189.cn` 登录，不打开窗口。需要联网；官网风控或人工验证可能导致登录失败。

## 安装

将本目录的 `ct189.py`、`requirements.txt` 放到青龙脚本目录（例如 `/ql/scripts/ct189/`）。在**实际执行任务的同一容器、用户和 Python 环境**中运行：

```sh
cd /ql/scripts/ct189
pip3 install -r requirements.txt
python3 -m playwright install --with-deps chromium
```

也可以在青龙依赖管理的 Python3 类别安装 `playwright==1.61.0` 和 `pycryptodome==3.23.0`，随后在任务运行环境安装 Chromium。浏览器安装和系统依赖通常需要管理员权限。示例环境为 Debian/Ubuntu glibc Linux；Alpine/musl 青龙镜像不能假定可运行 Playwright 官方 Chromium，应改用兼容 glibc 的运行容器。重建容器后须保留依赖或重新安装。Chromium 占用较多磁盘和内存，本脚本逐个账号运行，避免同时启动大量引擎。

## 账号变量

在青龙「环境变量」中添加 **一个** `CT189_ACCOUNTS`，其值支持多行：

```text
18900000001#001234#主号
18900000002#005678#副号
```

以上是虚构示例。每行 `手机号#数字服务密码#备注`，备注可省略，不要给整个变量添加 shell 引号。密码必须是字符串，保留前导零。不支持 `&` 拼接，备注不能包含 `#` 或换行。重复手机号或任意一行错误时，整个批次在联网前拒绝执行。

也可使用 JSON，适合包含特殊字符的备注或停用账号：

```json
[
  {"phone":"18900000001","password":"001234","label":"主号","enabled":true},
  {"phone":"18900000002","password":"005678","label":"副号","enabled":false}
]
```

最多 200 个账号。网页账号、网页启停设置与青龙变量各自独立；青龙的 `enabled:false` 才会跳过该账号。网页导入格式为 `手机号#备注#分组`，不接受密码，不要直接混用。

## 任务命令

先检查配置（不联网，也不需要加载浏览器依赖）：

```sh
python3 /ql/scripts/ct189/ct189.py --validate
```

手动执行登录确认：

```sh
python3 /ql/scripts/ct189/ct189.py --tasks login
```

登录后只读查询活动 310 资格：

```sh
python3 /ql/scripts/ct189/ct189.py --tasks login,activity
```

领取两个权益活动（每个任务只对每个账号提交一次官方领取流程，不自动重发领取请求）：

```sh
# 周五狂欢日：味多美 10 元服务兑换券
python3 /ql/scripts/ct189/ct189.py --tasks login,friday_wdmei

# 权益福袋：10 元翼支付通用权益金
python3 /ql/scripts/ct189/ct189.py --tasks login,rights_bag_cash
```

在青龙新建定时任务，命令填写上面的 Python 命令，例如每天 07:17 执行：`17 7 * * *`。先手动运行确认容器依赖和登录可用，再启用定时。也可设置 `CT189_TASKS=login,activity`，命令行 `--tasks` 优先。

- `login`：先查询缓存会话；号码完全一致才复用，否则进行一次账密提交并重新核验。只重试匿名初始化，不自动重发密码请求。
- `activity`：登录核验后查询资格接口，只报告查询是否成功，不领取、不推断奖励。业务拒绝会记失败，即使 HTTP 为 200。
- `friday_wdmei`：先读取活动 315 的资格和默认权益，再调用官网预校验及领取流程，默认权益为味多美 10 元兑换券。
- `rights_bag_cash`：按活动详情响应查找权益福袋活动，再读取资格和默认权益，默认权益为 10 元翼支付通用权益金。
- 领取类任务只允许一次官方提交；资格不足、已领取、活动结束、库存不足和预校验失败都会记为失败，网络中断不会自动重发领取请求。
- 单个账号失败不影响后续账号。退出码 `0` 表示启用账号全部成功（全停用也为 0），`1` 表示部分/全部账号执行失败，`2` 为配置/环境错误，`130` 为主动中断。

## 会话和日志

默认会话缓存为脚本旁 `.ct189-cache/`，也可通过 `CT189_CACHE_DIR=/ql/data/ct189-cache` 或 `--cache-dir` 指定持久目录。网页会话不与青龙共享。

按手机号哈希隔离浏览器目录；关闭前显式保存官方域名的 Cookie，下次启动恢复后再核验号码，包含不会自动随浏览器配置保留的会话 Cookie。运行锁阻止同一缓存目录的定时任务重叠，不同缓存目录之间不互斥。缓存目录权限设为 700，新文件采用 600；密码只从环境读取，不主动写入文件。浏览器配置和 `session.json` 含 Cookie，必须作为凭据保护，勿上传仓库或共享。删除缓存会要求下次重新登录；请先停止任务，再删除缓存目录。

日志只输出掩码号码、固定任务名和结果，不输出服务密码、Cookie、上游原始响应或异常详情。备注不输出，避免用户把敏感内容填入备注。青龙自身保存的环境变量仍含密码，请保护面板权限。

## 后续扩展签到和权益

在 `TASKS` 注册表添加处理函数 `handler(client, account)`，任务入口会先保证登录号码匹配；通过 `client.request(官方路径, 请求体)` 发起请求。须同步更新请求路径白名单，针对真实接口的业务成功条件编写测试。领取类任务应增加显式启用项、结果核验和防重复机制，禁止沿用匿名握手的重试策略自动重发领取。不要把密码作为命令行参数或打印调试响应。
