# 全球通网龄直升

依据用户提供的「全球通网龄直升」「全球通网龄直升1」「全球通网龄直升金卡」网页源码归档及「全球通网龄直升订购.har」实现。金卡归档与直升1归档中的主要业务脚本及 app 脚本内容相同。主要业务代码位于官方 `chunk-172b90d6.ee9ad0e6.js`，加密封装位于 `app.24aaf00a.js`。归档中的响应只作为样例，不视为任意账号的实际资格；归档名称也不能作为实际匹配金卡的依据。

## 入口和凭证

Public 账号操作菜单、用户管理账号菜单提供「全球通网龄直升」。沿用现有 10086 CK → COC 单点登录票据流程，生成 `/coc/web6/ageFeedPackage/` 链接，实时附加 token。页面固定使用 `pageId=1889487239237201920` 和用户指定的 `channelId=P00000115802`，不保存用户提供的示例 token。

订购页位于「业务订购 → 全球通网龄直升」。账号凭证按 `age_feed` 目标缓存并加密存储；使用前调用 `activities/common/queryUserInfoNew` 验活，失效时走现有凭证维护与重新置换流程。管理员也可使用临时手机号验证码登录。订购权限和账号归属校验沿用现有业务订购机制。

## 资格及档位

先查询 `pkg/contract/common/newProductRelation`，传入三种正式 goodsId、`type=20`、当前 userId。官方在 `isOrder` 为真时，将已有关系的 goodsId 映射为产品编码后进入 `goOrder` 获取协议，并没有直接禁止受理。自动匹配沿用此分支，同时提示已有业务关系和重复办理风险；关系无法映射时不猜测产品，提示手动选择档位。

未办理时依次查询 `activities/common/queryUserInfoNew` 的 `userChinaMobileage`、`editor/common/proxy/toC/gsmLabelQuery` 的 `data.entity.gbrandlevelInfo.gbrandLevel`、`pkg/common/queryMobileTagNew` 的定向资格。定向参数为 `tagIds=02519304000160`、`channelCode=025193040002`、`eventCode=eventJE000000160` 和上述渠道编码。

实际判断以源码条件为准：网龄至少 20 年（部分埋点文案误写为 10 年），全球通等级既非普卡也非非全球通，且当前等级不高于定向返回的目标档位。只采用 `resultCode=0000` 时第一个 `productInfos` 的 `products` 标签。

| 标签 | 直升档位 | 正式 productCode | 关系查询 goodsId |
| --- | --- | --- | --- |
| 001 | 银卡 | 100000099780 | 2025999900045799 |
| 002 | 金卡 | 100000099781 | 2025999900045800 |
| 003 | 白金卡 | 100000099779 | 2025999900045801 |

页面默认自动匹配，也可手动选择上述三个正式档位分别尝试办理。未发现钻石、卓越钻石对应的本活动正式产品，不猜测或混用其他活动编码。服务端只接受 `auto` 或这三个正式 productCode；页面 ID、渠道编码固定，拒绝任意产品及沙箱产品。

手动选择时仍查询业务关系、网龄、等级、定向结果并如实展示；本地资格不符不再直接封锁尝试入口，也不伪装成资格通过。只有成功获取该档位的官方协议及序列号后，才可发送验证码和确认订购，最终受理结果由运营商决定。认证失败、查询接口异常和协议缺失仍中止流程，不能当作资格失败后继续下单。

切换档位需重新获取协议、重新勾选同意，清除输入的验证码及旧结果；旧验证码不能沿用到新档位，已开始的 60 秒短信冷却不因切换档位或重新核验而清除。同一会话同时只允许一个产品核验请求，避免不同档位的协议和编码混用。下单结果未知时，本会话禁止重新核验和换档位继续下单，须先核对官方已订业务。

## 协议及订购顺序

1. `personalization/page/getDefault` 初始化活动页面配置。
2. `grocer/copyWriting/page/query` 查询活动规则，遵循源码使用公共规则产品 `100000096245`、省份 `100`、`configType=2`，与实际订购产品区分。
3. `grocer/protocol/prov/queryProtocol` 使用实际匹配产品、手机号、userId、归属省、页面 ID 和 `verifyType="0"` 获取协议及 `protocolSequenceId`。规则和协议均使用 Meteor v2：随机 AES-128-ECB 密钥、RSA 加密 Base64 密钥、双层 Base64 请求密文；使用同一 AES 密钥解密 `returnData`。
4. 用户阅读协议后调用 `user/smsCode`，传 `mobile/productCode/pageId/userId/smsCodeTypeEnum="505"`。成功后 60 秒冷却，失败不启动冷却。
5. 用户提供六位验证码并输入「确认订购」后，先调用 `user/loginCheck`，传 `mobile/userId/smsCode/productCode/smsCodeTypeEnum="505"/verifyType=0`。
6. 校验成功后才调用 `pkg/order/bookProduct`，传 `pageId/productCode/touchCode/verifyType=2/sourceUrl/protocolSequenceId`。本入口无 sellerId，故不附加。sourceUrl 使用网龄直升路由，不复用钻石路由，不附加临时 token。

短信校验及订单接口按官方源码使用普通 JSON。HTTP 失败或响应异常不能当作成功；提交订单后通信失败视为结果未知，禁止直接自动重试，需先核对官方已订业务。

## 验证范围

`npm run test:age-feed` 离线模拟资格分支、三档产品映射、Meteor 请求与响应、三档手动选择后的协议/短信/校验/订单一致性、失败重试、换档位短信冷却、并发核验和未知订单保护，不发真实短信、不产生真实订单。`src/tests/age-feed-browser.mjs` 验证桌面和移动端的入口、自动匹配、手动三档切换、资格参考、协议重新确认、错误弹窗和账号切换。

新增 HAR 记录了 `505` 订购短信发送及校验，但未记录最终 `pkg/order/bookProduct`，且响应未附正文；因此不能据此宣称订单成功或获得了某档资格。最终下单参数依据源码 `goOrderAjax`，三档产品编码映射依据生产环境映射，接口响应形态结合 ZIP 中保存的响应核对。

真实资费、合同和最终办理资格以运营商当前接口及用户确认的协议为准；本轮未执行真实订购。

## 跳转失败排查

导入 CK 时记录的本地有效期不代表运营商实际登录态有效。首页返回 302 登录重定向、200 登录页面或仅下发 Cookie，均不能作为验活成功；首页须返回 200 且包含用户上下文的有效 csrf。获取 COC 票据返回登录页面时，提示重新登录或导入 `wx.10086.cn` 的完整 CK，保留原有凭据。

跳转票据和凭证置换的预期失败使用 410（登录态不可用）或 424（上游依赖失败）返回 JSON，避免公网代理将本站 502 替换成 HTML 错误页。临时 HTTP 错误不会仅凭状态码判定为 CK 失效。`npm run test:coc-sso` 覆盖登录页面、重定向、临时异常及网龄直升与卓越钻石的有效票据传递。
