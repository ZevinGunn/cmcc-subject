# 全球通每日签到、补签与盲盒抽奖

使用 cookie-app 自有持久化调度，不依赖 Codex 客户端保持打开。运行 cookie-app 的主机与服务必须在线。

默认配置为北京时间每天 08:00，范围为所有未禁用且有云盘会话、全球通 Token 或 10086 CK 的账号。每次触发重新读取号池，新账号自动纳入；存在凭据不等同于有效，运行时仍需查询验证。云盘过期且无独立可用凭据的账号记录需要补登，不会伪报成功。

## 执行顺序

每个号码依次完成以下步骤，然后进入下一个号码，全程串行：

1. 校验云盘主凭据，保留各渠道独立状态。
2. 查询当天签到状态；存在官方可签到日期时提交一次，并回查确认完成。
3. 查询补签日期，按日期顺序逐项完成补签任务。剩余补签次数为 0 时立即停止。每次提交后读取最新状态，失败后也不能使用旧额度继续补签。
4. 完成官方清单中已开放且未完成的盲盒任务，回查确认结果。
5. 在官方剩余机会与本阶段上限内逐次抽奖；每次确认次数变化后才能继续。抽奖超时、响应不完整或次数未变化时停止本轮抽奖并记录，绝不自动重发。抽中奖品结果写入任务明细，需确认领取或填写资料的奖品在全球通专区处理，本任务不自动提交领奖资料。
6. 校验 wx10086 CK，失效、缺失或到期时重新置换并验证身份与核心查询后保存。

签到、补签和盲盒分别记录结果，某一环节失败继续执行其他独立环节与其他号码。任务明细可在管理页查看。

## 续期规则

- 全球通 Token 优先实际查询复用，明确返回未登录或过期时重新置换，有界重试；HTTP 403、网络超时本身不是凭据过期证据。
- 云盘主凭据只在明确认证失败时标记失效。目标业务暂时失败不清除云盘或其他渠道凭据。
- 云盘直达全球通落地页未确认登录时，使用新签发的 `017018` 票据建立全新 wx10086 登录，验证手机号与核心查询，再通过官方绑定入口取得全球通 Token 并查询登录状态验证。此路径使用当前明文 V2 票据协议，不重新启用历史的云盘 Web 加密直换路由。
- wx10086 经全球通换票遇到空票据时，先调用官方 `checkLoginStatus.action`。只有明确未登录才续期一次；已经登录但空票据保留目标业务拒绝提示。
- 保存派生凭据前检查云盘登录代际，避免旧结果覆盖用户刚完成的新登录。续期不更改最后一次主动登录时间或方式，WX 期限使用官方 Cookie 期限。
- 云盘主会话本身过期通常仍需验证码补登，不能凭失效会话承诺无条件自动续期。

## 调度与操作

`npm run global-daily:configure` 仅查看计划。

`npm run global-daily:configure -- --enable --time=08:00` 幂等创建或更新该计划。检测到多个此类型的全账号计划时停止配置，避免额外创建重复计划。

管理页“新建自动化计划”及“批量任务”中提供“全球通每日签到+补签+抽奖”。原“一键补签+一键盲盒”行为不变。新任务不执行周三拼图、订购、退订等无关功能。

计划与触发记录均存储在数据库，服务重启后保留。每天执行时间之后恢复服务可当日补跑；唯一触发键防止重复扫描重复运行。不自动重放跨日任务，也不自动重放进程中断时结果不确定的抽奖。中断任务标记失败，需查看明细后决定人工重试。

盲盒任务编号与阶段规则按已核实的活动源码使用；目前核实至 2026 年 10 月。遇到新一期未知清单会明确记录“任务清单需更新”，保留签到、补签和凭据维护，不盲目沿用旧月份任务编号。

## 验证

`npm run test:global-daily` 覆盖顺序执行、零额度跳过、认证恢复、响应丢失后回查、阶段上限、抽奖结果不明时停止以及当日补跑判断。`npm run test:yunpan` 覆盖云盘与 WX 备用置换、登录代际保护、空票据认证判断和身份匹配。
