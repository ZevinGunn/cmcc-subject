# 云盘登录与全球通、云手机、云应用接入

## 行为与能力

账号登录弹窗恢复“云盘登录”。先完成官方滑块，发送云盘短信验证码，再执行 Web 登录；成功后加密保存云盘会话，置换全球通 `access_token`，再由全球通签发 10086 业务票据取得真实 CK。只有新 CK 的账号匹配与核心查询均验证成功后才保存。下游失败仍保留已经成功的云盘、全球通登录，并以 warning 返回部分成功。

管理员账号页、公开账号页、用户管理与 V2 账号详情提供云服务入口。全球通签到、星动日补签、奖品补领、盲盒抽奖及批量任务可使用云盘置换的全球通 Token。原有确认信息、活动状态校验、每日任务记录和账号访问范围仍生效。只有云盘会话时，10086 业务查询、预约等入口仍不可用。

旧的云盘直连 10086 路径仍不使用。新增“云盘 → 全球通 → 10086”链路不依赖旧开关；旧 refresh/sso-link 路由作为新链路的兼容别名。

## 账号状态与操作菜单

云盘会话与 10086 CK 独立保存和判断。已保存云盘登录的账号显示“已登录”，旧 10086 CK 的失效记录、短信窗口或到期时间不会作为云盘登录失败或到期依据。云盘没有已证实的固定有效期，不标注“永久”或人为推算长期期限；上游拒绝换票时仍显示实际错误。

只有云盘会话时，账号详情仅展示手机号、全球通等级/归属地/网龄及全球通活动状态；不展示 10086 的主套餐、号码星级或周三拼图。10086 登录方式仍可选择。同一账号保留两种凭据时，有可用 10086 CK 才展示 10086 专属功能。

公开账号页面的三个云盘功能（置换全球通 Token、跳转云手机、跳转云应用）移入右侧操作菜单。宫格与列表共用菜单，按全球通、云服务、10086 服务和账号管理分组，双列排列，重新登录固定置顶。菜单支持上下方向键、Home/End、Escape、焦点恢复与视口内滚动；跳转结果不随菜单关闭丢失。生成链接两分钟未使用后要求重新生成，该时间是本地使用提示而非上游票据期限。

10086 分组新增“置换 10086 CK”和“跳转 10086”。已有云盘或全球通 Token 的账号可直接使用，无需重复输入 10086 短信。取得并验证新 CK 后，原有套餐、已订业务等入口恢复显示；失败时不启用未验证的能力。管理员、用户管理和 V2 云服务入口同步支持全球通 Token 账号。

## 协议

| 功能 | 云盘票据与后续流程 |
| --- | --- |
| 全球通跳转 | 原样 Authorization → 明文 `POST /user/querySpecTokenV2`，`{"toSourceId":"001191"}` → 全球通 `ssoTokenLogin.action`，携带 token、targetSourceId、enableShare 和完整编码的 backUrl |
| 全球通 Token | 新签发的 001191 票据 → 全新 Chrome 上下文执行官方页面 → `checkLoginStatus.action` HTTP 200 且 status 严格等于字符串 1，同时存在新下发 access_token → 加密保存全球通 Token |
| 10086 CK / 跳转 | 全球通 access_token Cookie → form POST `getCmpSSOTokenNew.action`，`targetid=017018` → 响应 data 业务票据 → `/website/sso/netUni?netUniBackUrl=编码后的newHome&net_token=新票据` |
| 云手机跳转 | 全球通 access_token Cookie → 同一换票接口，`targetid=001216` → `https://cloud.139.com/#/?token=…&targetSourceId=001216&loginType=0&channelSrc=02190`（官方星动日组件渠道）；原云盘直接方式 02207 保留在底层实现 |
| 云应用 CAPP | 全球通签发的 001216 票据 → `/uniphone/user/tokenValidate`，version 为字符串 1.2、pintype 为整数 5 → 云手机业务 Token → `/uniphone/user/getRcsToken`，targetSourceId 为 001304 → tmpToken → `https://capp.139.com/#/?i=…&token=…&targetSourceId=001304` |

云盘明文 SSO 请求不带旧 Web 加密请求头，不改写 pc/mobile 身份。toSourceId 必须匹配目标，不能留空、混用或将登录 Cookie 内的 ssotoken 直接填进业务入口。全球通跳转票据与置换 Token 使用不同的新请求；生成的跳转票据不被服务端提前消费。应用 i 参数沿用已提供源码的入口，不支持任意 URL 或应用参数。

## 接口与运行

- `POST /api/accounts/yunpan/sms/send`：phone、可选 nationCode、官方滑块 puzzleVerifyCode。缺少证明不发短信。新短信 CBC 请求仅在 HTTP 200、明确 01000019 解密错误且确认旧 CBC 响应时兼容重试一次；不自动重发超时、频控和普通失败。
- `POST /api/accounts/yunpan/login`：phone、code、可选 label/nationCode/publicLinkId。登录会话按账号保存，全球通失败以 warning 返回部分成功。
- `POST /api/accounts/:id/qqt/token`：可选 force；支持云盘会话独立置换。
- `POST /api/accounts/:id/qqt/sso-link`：优先为云盘账号新签发全球通跳转票据；无云盘会话时保留原 10086 流程。
- `POST /api/accounts/:id/yunpan/business-link`：target 仅接受 cloudphone 或 capp；通过全球通签发实时票据，支持云盘或全球通 Token 账号。公开请求须通过账号范围检查。
- `POST /api/accounts/:id/qqt/10086`：在全新 Cookie 环境中换票、校验、加密保存 CK；兼容别名 `yunpan/refresh`。
- `POST /api/accounts/:id/qqt/10086-link`：签发单独的新票据用于浏览器跳转，不在服务端提前消费；兼容别名 `yunpan/sso-link`。

部署服务为 cookie-app，使用 Node 20 与固定 Playwright 1.64.0。Chrome 路径默认 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，可用 YUNPAN_CHROME_PATH 指定。浏览器最多同时运行两个实例，其他请求进入有界队列；同账号 Token 置换合并并发请求。只读查询遇到已确认的认证错误可重新置换一次；不会自动重复签到、补签或抽奖等操作。

全球通 Token 的五分钟缓存是本地复用窗口，不等于上游有效期。去掉仅因云盘登录而推断 10086 Cookie 有效三十天的旧逻辑。链接不持久缓存，生成后应尽快使用。日志只记录目标、HTTP/业务状态、响应编码及 Cookie 名称，不记录真实票据、验证码和 Authorization。

10086 CK 期限取 `shareToken` 与 `d.sid` 的 Set-Cookie 到期时间较早者；本次实测约 30 分钟，不能承诺固定时长或借用云盘期限。来源保存为 `qqt_sso`，续换不改写最后一次登录方式、登录时间或短信登录窗口。共享 CK 维护服务在缺失、失效或到期时续换，正常有效 CK 先复用。同账号并发置换合并，全球通明确业务拒绝时最多通过云盘更新 Token 一次；网络异常不触发登录循环。

10086 换票不携带历史 WX Cookie，也不将全球通 Cookie 发送给 WX；重定向只允许 HTTPS 的 wx.10086.cn、限定次数。保存前核验固定 newHome 的手机号和 csrf，并检查只读核心查询的 status=0、data.resultCode=0000。官方 newHome 可能只返回前三位＋四星号＋后四位，按该格式与账号匹配；该证据不等同于上游返回完整手机号。不同号码、空值或异常格式拒绝保存。生成跳转链接与收集 CK 分别签发票据，避免一次票据提前消费。

## 验证与边界

新增模拟协议测试覆盖目标隔离、请求头、拒绝伪成功、CAPP 三步换票、短信兼容重试限制、新浏览器认证成功与失败。浏览器测试覆盖 1440/390 宽度、滑块失败重试、冷却期重复回调不重发、短信登录、全球通和云服务跳转控件；全部外部请求被拦截。

账号菜单回归测试覆盖云盘携带旧过期 CK、10086 单独登录、双凭据登录、宫格/列表、1440 桌面和 390 宽度两种手机高度、菜单键盘操作、跳转生成及失败反馈。测试全部使用模拟 API，不发送真实短信或运行真实活动。

使用已获授权的本地测试会话真实验证：全球通全新浏览器置换成功；新的云手机票据生成成功；CAPP tokenValidate 与 getRcsToken 均成功并生成云应用链接；全球通签到状态与盲盒状态只读查询成功。未触发真实签到、补签、抽奖、领奖或订购；CAPP 应用内部使用流程未验证。

新增 HAR `全球通置换wx.10086.har` 的请求 172→176→192 证明全球通 017018 票据与 WX net_token 相同，并成功登录周三活动；749→780 证明 001216 票据用于云手机 tokenValidate。仅该 HAR 尚不能证明全部 10086 查询。随后使用本轮实现和 HAR 授权会话进行独立只读实测：全新票据取得新 shareToken/d.sid，账号脱敏信息匹配，余额/套餐核心查询返回业务成功；全球通到云手机 tokenValidate、CAPP getRcsToken 均返回业务成功。未验证每一种活动/业务操作，真实退订、订购、领奖等仍按原有授权与确认流程执行。

`qqt-sso-unit` 覆盖严格业务成功、票据目标、全新 Cookie、HTTPS/域限制、号码脱敏匹配、核心查询伪成功拒绝、真实期限、失败保留凭据、有限认证重试、并发合并及不覆盖新登录。账号菜单浏览器测试增加全球通单独账号、10086 置换失败仍保留云盘成功、置换成功恢复已订业务入口；桌面、手机、宫格、列表和键盘均使用模拟 API。

发布通过仓库 `npm run release`，核验 API 版本及公网 HTML/JS/CSS 内容。账号会话、HAR、日志、运行数据与测试凭据不进入 Git。
