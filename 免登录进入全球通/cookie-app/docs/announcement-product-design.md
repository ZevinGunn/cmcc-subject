# 公告、消息提醒与新手指引产品设计

## 1. 目标与范围

本次在 cookie-app 增加统一公告中心，使管理员可以创建、编辑、定时发布和停用富文本公告；用户在 public 页面可以通过右上角通知入口查看当前有效公告，并按照公告策略获得适量提醒。同时为首次访问 public 的用户提供可跳过、可再次打开的新手指引，为 V2 工作台提供与真实布局一致的骨架加载状态。

本期范围：

- 管理端公告列表、创建、编辑、删除、启停、预览和 HTML/TXT 内容导入。
- 立即发布、定时发布、可选失效时间。
- 重要公告，以及强、中、弱三个提醒等级。
- public 通知铃铛、未读数量、公告列表、富文本详情、自动弹窗和提醒状态。
- public 首次访问新手指引，以及后续从帮助入口重新打开。
- V2 工作台首屏骨架。
- 首屏请求链路和构建产物的第一阶段性能优化。

不在本期：短信/PushPlus 外部推送、公告附件上传、复杂受众分组、多人审批、公告版本回滚、浏览器推送权限申请。

## 2. 用户角色与入口

### 2.1 管理员

V2 左侧“用户与访问”增加“公告管理”。页面默认展示全部公告，可按状态和等级筛选。主要操作为新建、编辑、预览、启停和删除。

### 2.2 public 用户

public 页面右上角提供两个紧凑图标按钮：

- 通知铃铛：展示未读 badge，点击打开公告列表。
- 帮助：点击重新打开新手指引。

移动端保持图标按钮尺寸不小于 36px，badge 固定在按钮右上角，不参与正常文档流，避免标题和按钮错位。

## 3. 公告字段与状态

每条公告包含：标题、富文本正文、等级、重要标记、启用状态、发布时间、可选失效时间、创建/更新时间。

发布状态由服务器时间动态计算，不依赖后台定时任务：

- 草稿/停用：`enabled = false`。
- 待发布：已启用且 `publishAt > now`。
- 发布中：已启用、`publishAt <= now`，且未过失效时间。
- 已结束：存在 `expireAt` 且 `expireAt <= now`。

管理员不能把失效时间设置为早于或等于发布时间。所有时间通过 ISO 8601 传输，界面按 Asia/Shanghai 展示。

## 4. 提醒规则

提醒判断只针对“发布中”的公告。重要标记优先于等级；自动弹窗每次只展示一条，关闭后再判断下一条，避免多层弹窗。

| 类型 | 自动弹出条件 | 用户操作 | 后续行为 |
| --- | --- | --- | --- |
| 重要 | 用户从未永久关闭该公告 | 知道了；不再提醒 | “不再提醒”后不再自动弹出，仍保留在通知中心 |
| 强 | 当天未自动展示 | 知道了；今天不再提醒 | 同一自然日不再弹出，次日可再次弹出 |
| 中 | 从未自动展示且未永久关闭 | 知道了；不再提醒 | 首次展示后默认不重复弹出；永久关闭状态被记录 |
| 弱 | 永不自动弹出 | 标记已读 | 仅通过通知中心主动查看 |

约定：

- “重要”是独立布尔属性，不是第四个等级；重要公告仍保留强/中/弱字段用于列表样式，但自动提醒按重要规则执行。
- 强等级的“当天”采用北京时间自然日。
- 点击公告列表项或打开自动弹窗即记为已读，未读 badge 立即减少。
- `readAt`、自动展示记录和用户主动选择的关闭记录相互独立。
- 被关闭的公告仍可从通知中心查看，直到停用或过期。
- 同一用户在不同设备共享服务端提醒状态。

自动弹窗选择顺序：重要优先，其次强、中；同一优先级按 `publishAt` 倒序。弱等级永不进入自动弹窗候选。

## 5. 新手指引

首次成功进入 public 功能页且公告弹窗队列处理完后，打开新手指引。指引以 4 个步骤覆盖现有页面中的真实控件：

1. 选择登录方式并完成账号登录。
2. 在账号区查看账号状态和执行日常操作。
3. 使用业务查询、商城查询和业务订购入口。
4. 通过右上角通知与帮助入口获取更新和重新查看指引。

用户可“下一步”“上一步”“跳过”或“完成”。完成或跳过均写入按用户隔离的本地版本键；当指引内容升级时增加版本号，可让用户重新看到新版指引。帮助按钮始终允许手动重开。未登录访问按浏览器访客键记录，登录后切换为用户 ID 键，避免不同账号互相污染。

## 6. 富文本导入与展示

管理员可导入 `.html`、`.htm` 或 `.txt` 文件，单文件上限 1MB：

- HTML 文件读取正文后进入编辑器。
- TXT 文件按纯文本导入并保留换行。
- 导入只填充编辑器，不会自动保存或发布。
- 编辑器提供标题、段落、粗体、斜体、有序/无序列表、链接和清除格式等常用能力。
- 保存时服务端进行白名单净化；客户端预览仅展示服务端可接受的标签与属性。
- 禁止脚本、事件属性、iframe、表单、内联脚本 URL 和危险协议。

public 详情正文需要支持标题、段落、列表、引用、链接、表格和图片的安全响应式展示；长链接和表格必须在移动端换行或横向滚动，不能撑破弹窗。

## 7. 界面状态

公告管理页必须覆盖：首次加载骨架、空列表、筛选无结果、请求失败、保存中、发布成功、删除确认、文件格式/大小错误。

public 通知中心必须覆盖：加载中、无公告、未读/已读、内容加载失败和提交提醒状态失败。提醒状态提交采用先更新界面、失败时回滚并提示，不能阻塞用户关闭弹窗。

V2 工作台骨架应复现标题、四个指标块、双栏内容和下方列表的稳定尺寸，减少数据返回时的布局跳动。

## 8. 验收标准

- 管理员可创建未来发布时间的公告；到达发布时间后，无需重启和后台任务即可出现在 public。
- 富文本中的危险标签和属性不会进入数据库或 public DOM。
- 未读 badge 数量与服务端状态一致，超过 99 显示 `99+`。
- 重要、强、中、弱分别严格执行上述规则，且同一用户跨设备一致。
- 公告弹窗优先于首次新手指引，二者不会同时出现。
- public 桌面与移动端的通知入口、弹窗和指引不遮挡主要操作。
- V2 工作台加载时显示结构化骨架，数据就绪后无明显布局跳动。
- 公告管理相关操作记录管理员身份和时间，并返回可追踪的 `requestId`。
