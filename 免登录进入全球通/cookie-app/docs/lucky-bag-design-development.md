# 福袋产品与开发设计

## 界面

统一业务选择新增标准/豪华福袋两个入口，沿用紧凑业务网格和原public/管理员返回路径。复用账号搜索、独立短信登录、协议展示与结果组件。页面明确显示：福袋版本、脱敏账号、主资费订购状态、当前权益、当前是首订/补选/更换。

权益是单选目录，标准5项/豪华4项；当前权益不可选，禁止跨版本自定义产品。已订主资费后的0元候选显示套餐内权益提示，并要求确认实时协议。返回上一步保留账号、清除协议和验证码；重新开始销毁旧会话。成功页增加刷新关系继续办理；结果待确认只提示官方核查，不自动转入下一次下单。

保持现有操作界面的密度、语义标签、焦点与键盘访问，移动端单列、桌面多列，不新增装饰动画；保留禁用、请求中、错误和部分信息状态。所有富文本使用已有清理后的SafeHtml，不执行源站HTML脚本。

## 服务架构

扩展现有 BenefitOrderWorkflow 为 lucky_bag，保持已有积木、智臻和App流程不变。新独立 luckyBagOrder 模块集中持有版本配置、九项权益映射、关系解析、目标选择和请求参数构造；通过注入的COC请求函数完成读取，便于真实契约的离线测试。公共会话服务处理生命周期、登录、加密、权限、冷却和最终结果。

专用状态包含 variant/mainOrdered/currentBenefitCodes/action。服务端首次选择、发送订购短信和确认前重新查询关系，若与已展示方案变化则要求重新选择；不靠浏览器传入的价格、组合码或主产品推断订单。主协议使用组合码，权益变更使用权益码，均由白名单映射产生。

Meteor补充到既有COC加密工具；每个请求的key仅服务端使用，处理returnData解密。登录继续Aurora，关系与下单继续明文JSON+Cookie。省份、userId来自独立登录响应，认证缺失则不允许进入产品流程。

## 状态与并发

initialized → login_sms_sent → authenticated → product_ready → selection_ready → order_sms_sent → ordering → finished。

每个福袋会话的异步操作加在途锁，包括验证码、查询和选择，避免并发请求覆盖Cookie或授权状态。同一手机号/版本订单仅允许一个在途提交；无幂等上游不做自动重试。提交前关系查询属于只读阶段，失败不表示已发订单；提交之后的连接中断/格式异常作为结果待确认。进程重启会失去内存会话和锁：本次沿用单实例架构，不声称具备跨实例幂等；多实例上线需改用共享会话/锁和持久化订单尝试记录。

成功后的刷新重新查询上游状态；刷新失败保留原结果与产品信息，刷新成功后清除旧结果，回到权益选择。若主资费仍未生效，显示等待生效并拒绝重复首订。更换后关系仍未反映目标时也等待生效，防止连续重复变更。

短信冷却按手机号与用途共享，切换福袋或重新开始不能绕过60秒冷却。已受理或结果不确定的订单按手机号与福袋版本记录目标权益，单进程内最多保护24小时；查询确认主资费已订且目标权益已生效后解除保护。此记录与锁不持久化，服务重启、多实例或24小时后仍需操作者先核查官方结果，不应依赖它代替运营商订单查询。
