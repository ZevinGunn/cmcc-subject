# 全球通与 10086 凭据恢复排查

## 已验证原因

2026-10-29 使用授权的尾号 4812 账号进行登录态与只读查询测试，未触发签到、领奖、订购或退订。

- 凭据并非没有保存：全球通 `access_token` 和 10086 Cookie 已加密持久化到凭据库；本次原有 10086 Cookie 已超过记录的有效期。
- 全球通 `checkLoginStatus.action` 返回 `status="1"`、已登录，但 `getCmpSSOTokenNew.action` 请求 `targetid=017018` 返回 `status="1", data=""`。原实现直接中断，无法恢复 10086 登录。改变 JSON/表单编码、使用新的云盘票据和完整浏览器会话均不能消除该空票据现象。
- 官方 `utils_index.js` 包含 `getCmpSSOParam.action` 取票流程。携带全球通 Token、官方 Referer，以及 `channelCode=66050&levelPass=false` 可取得 `data.token`；用于 10086 单点登录后，号码匹配且核心余额查询成功。省略官方 Referer 的诊断请求曾返回 HTTP 500，故不能省略。
- 全球通缓存原先超过五分钟就重新由云盘置换，没有先验证原 Token。页面刷新流程也可能强制置换，造成不必要的登录链路调用。
- 原全球通专区入口向浏览器返回云盘短票链接，未保证服务器已缓存全球通和 10086 登录。该直达链接在本次全新浏览器中可成功，未复现用户浏览器失效的唯一原因；改用已验证的官方 10086 bind 单点登录入口，新浏览器登录状态确认成功。

## 修正后的流程

1. 全球通 Token 在五分钟校验窗口内复用；超出窗口先查询官方登录状态，仍有效就只更新时间。仅明确失效或用户显式强制刷新时重新使用云盘登录，并加密保存新 Token。网络异常不当作凭据失效。
2. 10086 CK 在校验窗口和实际到期时间内复用；需要验证时查询首页。明确失效、缺失或已到期才进入全球通换票。
3. 10086 换票先调用 `getCmpSSOTokenNew.action`；成功但票据为空时，补调用一次 `getCmpSSOParam.action`。备用接口只允许用于 10086，不把其票据用于云手机或云应用。
4. 新 10086 CK 仍须在空 Cookie 容器中完成官方跳转、当前号码核对、CSRF 获取、核心查询成功和真实到期时间校验，然后加密保存。不得因 HTTP 200 就认为置换成功。
5. 全球通专区入口准备并缓存可用凭据后，由官方 10086 bind 接口签发新的全球通浏览器跳转票据。每次跳转新签发，短票 URL 不作为长期缓存，也不在服务端先消费再交给浏览器。
6. 显式 10086 置换接口默认复用有效 CK，`force=true` 才强制置换。全球通查询页面刷新不再等同于强制更换 Token；业务明确失效时仍保留原有的一次恢复重试。

## 验证范围

- 离线回归覆盖空票据备用接口、错误状态、异常响应、限定一次备用请求、缓存验活、失效更新、网络错误不更新、并发合并及新登录竞争保护。
- 4812 实测：已有全球通 Token 复用成功，过期 10086 CK 恢复成功且数据库重新读取与结果一致，第二次访问复用同一 CK，官方全球通专区新浏览器确认已登录。
- 官方未向此流程提供可依赖的全球通 Token 固定有效期限，因此采用官方验活和业务失效反馈，不推测 Token 寿命。10086 按实际 Set-Cookie 到期时间保存，不将校验时间当作到期时间。
