# 爱购商城业务订购产品设计文档

版本：1.2｜产品位置：V2 业务订购 → 爱购商城

## 1. 产品目标

让有业务订购权限的管理员或账号用户，在不暴露爱购凭据的前提下，对已知或自定义爱购权益业务执行一次明确、可核对、可审计的订购尝试。

成功标准不是“所有业务都订购成功”，而是“所有合法参数都能越过客户端资格限制尝试提交，并准确呈现爱购服务端的最终结果”。

## 2. 用户与权限

- 管理员：可选择全部未停用账号。
- 普通用户：仅可选择自己关联的账号，且必须开启 `businessOrder` 权限。
- 无权限用户：接口返回 401/403，页面使用现有全局错误处理。
- 账号标识：始终展示标签与脱敏手机号，不展示手机号明文。

## 3. 核心用户流程

### 3.1 第一步：选择账号与业务

用户选择账号和默认业务，或选择“自定义 SKU”只输入 SKU ID。页面 code、channelCode、selfChannelCode 和 referer 收入高级业务参数。已知 SKU 自动带出完整配置；未知 SKU 使用通用权益上下文。

“核对实时商品”是进入短信步骤的必要动作。账号或任一业务参数变化后，已核对商品和历史结果立即失效，避免参数与展示不一致。

### 3.2 第二步：核对商品

页面展示实时商品名称、SKU、价格、订购协议类型和协议内容。未知 SKU 使用通用上下文时显示明确警示。只有上游商品/套餐信息核对完成，才开放短信与提交区域。

协议内容经 HTML 清洗后显示在可折叠区域；不执行脚本、不信任上游样式。

### 3.3 第三步：短信确认

用户发送验证码，按钮进入固定宽度加载态，成功后 60 秒倒计时。验证码使用 `one-time-code` 自动填充，仅保存在组件内存中。

动态风控参数仅在权益协议下显示，位于独立高级折叠区。套餐协议使用自身的 Aurora 加密、短信校验与手机证明，不展示爱购 `gr-risk-*`。

### 3.4 第四步：提交订购

页面明确说明：客户端不拦截资格、库存和页面状态，始终尝试提交；最终结果由爱购服务端决定。

提交前必须同时满足：实时商品已核对、验证码为 4-8 位数字、用户输入“确认订购”、当前没有进行中的请求。

## 4. 页面信息架构

- 顶层业务选择：沿用统一业务订购页面的紧凑网格，爱购商城图标为 ShoppingBag。
- 主体：四个同级编号区块，不嵌套卡片。
- 状态信息：账号与业务 → 商品事实 → 短信 → 确认 → 结果。
- 颜色：中性色为主；绿色表示已核对/受理，琥珀色表示有后果的提交与业务拒绝，红色表示请求错误。
- 圆角：6px；无渐变、无装饰图形、无营销式大标题。

## 5. 状态设计

- 初始：仅显示账号与业务参数。
- 商品加载：核对按钮显示 spinner 并禁用。
- 商品错误：保留用户参数，显示具体错误与 requestId（由 API 客户端追加）。
- 商品就绪：显示实时事实并开放短信、确认区。
- 短信发送中：发送按钮禁用且不改变尺寸。
- 短信回调：无论业务成功或失败，都展示上游消息、业务码和“验证码接口具体响应”；仅发送成功后进入 60 秒冷却。
- 订购中：提交按钮禁用，阻止并发重复提交。
- 受理成功：绿色结果区，显示业务码、消息、预检和 attempted=true。
- 业务拒绝：琥珀色结果区，已到达最终接口时标题为“已提交但未受理”；短信校验失败时标题为“订购前置验证未通过”。
- 风控准备：最终结果显示 C1 设备令牌、WASM 参数和设备指纹是否实时获取/提供，不显示参数值。
- 响应详情：无论成功、业务拒绝或上游 HTTP 失败，都展示脱敏后的具体响应和对应消息。
- 重新开始：最后一步完成后始终提供，清理验证码、结果、冷却和风控内存状态。
- 网络/鉴权错误：红色警示区，不清空已核对商品。

## 6. 强制尝试规则

- 不根据活动时间禁用提交。
- 不根据库存、joinStatus、qualification 或黑名单禁用提交。
- 预检失败后继续调用 directOrder；预检结果随最终结果返回。
- 不绕过服务端身份认证、短信验证、加密协议或风险校验。
- 不自动重试订单，不批量并发提交，不把失败业务码改写为成功。

## 7. 响应式与可访问性

- 最小宽度 320px；表单在窄屏单列，短信与按钮在宽屏双列。
- 所有输入具有可见标签；验证码使用数字键盘和一次性验证码语义。
- 账号下拉使用现有 viewport-aware portal，支持键盘导航、Escape 和边缘翻转。
- 交互反馈只使用颜色、spinner 与轻微按压缩放；无高频进入动画。
- `prefers-reduced-motion` 下不依赖运动表达状态。
- 长协议限制高度并允许内部滚动，标题与后续操作保持可达。

## 8. 文案规范

- 使用“核对实时商品”，不使用“解析成功”以免暗示资格。
- 使用“提交订购”，不使用“立即开通”以免在服务端确认前承诺结果。
- 业务失败使用“已提交但未受理”，明确区分网络未到达与服务端拒绝。
- 强制尝试提示固定为：“客户端不拦截资格或库存状态，将始终尝试提交；最终结果以爱购商城返回为准。”

## 9. 数据与隐私

- 前端不接收 Cookie、token、refreshToken 或手机号明文。
- 商品协议使用 sanitize-html 清洗。
- 动态风控字段不落 localStorage、sessionStorage 或数据库。
- 错误详情只展示脱敏后的上游 data；用户可用 requestId 联系运维。

## 10. 验收标准

- 已授权账号能加载爱购校园版实时商品。
- 默认目录同时包含 cookie-app 与 coc-rights-order-local 中已知的 7 个业务。
- 仅输入未知 SKU 时能使用通用默认参数核对，并显示渠道兼容性提示。
- 星巴克联合会员使用 `bookProduct`，不会调用 `directOrder`。
- code 或业务参数变化会清除旧商品和旧结果。
- 短信成功后有 60 秒冷却且不能重复点击；短信业务失败时显示原始回调且允许重新发送。
- 确认订购会实时准备 C1 设备令牌，并在会话已有 `BSFIT_DEVICEID` 时自动使用；WASM 参数只接受当前浏览器生成值。
- 未输入验证码或确认文本时不能提交。
- 黑名单/资格状态不会使提交按钮永久不可用。
- `code=0` 显示受理成功；`code!=0` 显示已尝试但未受理。
- 结果区显示“已到达订购接口：是/否”、脱敏具体响应与“重新开始”。
- 320px 移动端和 1440px 桌面端无横向滚动、文字遮挡或按钮移位。
- 键盘可完成账号选择、表单填写和提交。
