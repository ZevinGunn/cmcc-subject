# 积木套餐与智臻会员订购产品设计及开发方案

## 1. 产品目标

在现有“业务订购”能力中增加两种经过真实接口验证的办理工作流：

- 积木套餐：独立短信登录，选择流量/语音/短信模组后聚合订购；
- 智臻会员：使用所选账号的 10086 SSO 登录新零售网关，选择会员档位后创建订单。

现有卓越钻石卡继续保留。三种业务共享入口、账号权限、结果表达和安全约束，但各自维护独立上游适配器与状态机。

## 2. 设计原则

1. 先选业务，再显示该业务真正需要的字段，不向用户暴露无效的通用参数表单。
2. 积木登录态与卓越钻石完全隔离；智臻令牌与 Cookie 也不进入其他业务会话。
3. 产品、模组、档位、规则和协议均实时读取；默认编码只用于定位活动。
4. 资格不通过可以“仍尝试提交”，但必须展示风险并要求再次确认。
5. 任何最终写入接口都不自动重试，不提供批量或定时订购。
6. 前端只接收脱敏摘要；Cookie、Token、完整手机号和验证码只存在于服务端短时内存。

## 3. 信息架构

沿用现有入口：

- V2 管理台：`/v2/business/order`；
- public 账号中心：`/business-order?accountId={id}`；
- 用户管理页账号操作中的“业务订购”。

订购页顶部增加紧凑业务选择器：

- 卓越钻石卡
- 积木套餐
- 智臻会员

切换业务会清理旧会话、验证码、协议确认和结果，避免跨业务复用敏感状态。

## 4. 页面流程

### 4.1 公共步骤

1. 选择业务和账号；
2. 建立对应登录态；
3. 加载实时产品；
4. 选择产品配置并执行资格检查；
5. 阅读协议；
6. 发送订购验证码；
7. 输入验证码和 `确认订购`；
8. 展示明确结果并清理会话。

### 4.2 积木套餐交互

- 账号选择后明确提示“该业务仍需单独短信登录”；
- 登录成功才加载模组；
- 流量、语音使用单选列表，短信使用可选复选列表；
- 固定显示月费合计和各资源摘要；
- 任一模组变化后，旧资格、协议和订购验证码全部失效；
- 资格失败时显示上游原文和“仍尝试提交”开关。

### 4.3 智臻会员交互

- 必须选择已有账号，不提供手输手机号；
- SSO 初始化成功后展示脱敏号码和省市；
- 档位列表按价格和版本展示，选中后加载详细权益；
- 重点提示“原主套餐可能失效”“次月生效”“最终以短信通知为准”；
- 资格、协议、验证码均绑定当前 `normId`。

## 5. 权限与入口

- 继续使用现有独立 `businessOrder` 权限；
- 管理员可操作所有有效账号，普通用户只能操作本人关联账号；
- public 页面只有已登录账号中心且权限开启时显示订购入口；
- 后端不信任前端的账号、工作流或会话归属信息，每个接口重新校验；
- 智臻工作流即使管理员也必须选择已有 Cookie 账号；积木允许管理员手输手机号，但仍执行独立验证码登录。

## 6. 后端架构

### 6.1 模块边界

- `api/services/cmccBenefitOrder.ts`：统一会话仓库、状态视图、归属校验和工作流分派；
- `api/services/cmccBuildingBricksOrder.ts`：积木 COC 登录、模组、资格、协议和聚合订购；
- `api/services/cmccPremiumMembershipOrder.ts`：新零售 SSO、加解密、档位、预校验、协议、短信和创建订单；
- `api/routes/benefitOrders.ts`：权限、账号范围、输入验证和标准响应；
- `api/app.ts`：挂载 `/api/benefit-orders`。

不把两套协议硬塞入现有 `cmccBusinessOrder.ts`。该文件保留卓越钻石职责，避免其单产品状态机被大量条件分支破坏。

### 6.2 统一会话状态

```ts
type BenefitWorkflow = 'building_bricks' | 'premium_membership'

type BenefitOrderStage =
  | 'initialized'
  | 'login_sms_sent'
  | 'authenticated'
  | 'product_ready'
  | 'selection_ready'
  | 'order_sms_sent'
  | 'ordering'
  | 'finished'
```

积木使用全部登录阶段；智臻在创建会话时完成 SSO，从 `authenticated` 开始。会话 TTL 15 分钟，每次有效操作续期。

### 6.3 结果模型

```ts
type BenefitOrderResult = {
  success: boolean
  uncertain: boolean
  accepted: boolean
  code: string
  message: string
  orderId?: string
  orderStatus?: string
  completedAt: string
}
```

`success` 表示接口明确成功；`accepted` 表示已受理但可能仍办理中；`uncertain` 只用于超时、连接中断或无法解析最终响应。

## 7. 前端架构

- `src/v2/lib/benefitOrderApi.ts`：统一类型化客户端；
- `src/v2/pages/V2BenefitOrderPage.tsx`：业务选择和公共流程壳；
- `BuildingBricksOrderPanel`：积木独立登录与模组选择；
- `PremiumMembershipOrderPanel`：智臻档位与新零售订单流程；
- 现有 `V2BusinessOrderPage` 作为卓越钻石面板复用或由统一页面调度。

桌面端保持高信息密度；移动端状态条横向滚动，模组/档位改为单列。固定格式控件使用稳定高度，加载状态不改变布局。

## 8. 安全与可靠性

- 日志过滤手机号、Cookie、Authorization、User-Token、验证码、协议中的客户信息和订单号；
- 上游富文本经 `sanitize-html` 服务端清理，前端再执行防御性清理；
- 短信接口 60 秒冷却，会话级防并发；
- 最终提交使用互斥锁，单会话不能并发订购；
- 修改业务、活动参数或选择项会撤销协议确认并清除验证码状态；
- 最终接口不重试；不确定结果要求先查询，避免重复受理；
- 内存会话在进程重启后失效，不持久化敏感凭证。

## 9. 测试计划

### 9.1 单元测试

- 两套 AES 加解密测试向量和 Base64 URL-safe 兼容；
- COC 普通/Base64 JSON 响应解析；
- 新零售 `{body}` 响应解密；
- 积木模组选择校验、费用合计和 `tyingProductCodes` 构造；
- 智臻嵌套预校验响应、协议回退列表和关联活动映射；
- 状态机非法跳转、会话归属、TTL、短信冷却和最终提交互斥；
- 资格失败时 `forceAttempt=false` 阻止、`true` 允许继续；
- 超时结果标记为 `uncertain` 且不重试。

### 9.2 UI 与构建

- 管理员和 public 两种入口；
- 积木独立登录提示与步骤变化；
- 智臻只能选择已有账号；
- 选择项变化清除协议状态；
- 桌面与移动视口无溢出、遮挡或按钮跳动；
- `npm test`、`npm run build` 全部通过。

### 9.3 真实接口验证边界

自动测试不发送真实短信、不提交真实订购。真实联调分三层：

1. 只读：SSO、产品、档位、规则和协议；
2. 人工确认后：发送短信；
3. 用户明确输入验证码和确认文本后：单次最终提交。
