# 旧版已订业务查询与退订

独立入口 `/legacy-business-query?accountId=...`，独立 API 前缀 `/api/legacy-business-query`。不替换 `/c` 与 `/shop-query`，也不修改它们的协议、会话或缓存。

## 登录与权限

使用账号的 wx10086 CK，经项目现有维护流程验证/续期后访问 `https://wx.10086.cn/website/spa/main/alreadyService/index`。仅以 JSON 读取页面 `user`，不执行上游脚本；核对 `telephone` / 解密后的 `wmhId` 与所选号码一致，读取当前 `csrf`。登录信息仅保存在服务端独立会话中，空闲 30 分钟过期，前端不接收 CK、CSRF 或上游原始响应。

### 旧入口跳转原因与原生 App 登录

2026-10-18 复查站内账号发现，普通 10086 首页能返回有效身份，但旧入口返回 302 → `/website/api/jumpApp/redirect/undefined/alreadyService` → `/cmcc-service/app-pages/main/businessQuery`。此前实现没有处理跳转，把一切非 200 都误报为 `SESSION_EXPIRED`。这与旧 HAR 中可直接打开旧页面的 App 渠道会话不同；不能据此承诺普通 wx10086 CK 一定兼容旧协议。

旧 HAR 内同时包含 App 会话直接打开旧页面的成功请求，以及另一个会话被转到新版的请求。因此“旧入口返回 302”不足以证明旧协议全网停用。上一版前端收到 `LEGACY_MIGRATED` 后主动导航新版，是用户遇到强制跳页的直接原因；现已删除这段导航及新版迁移提示。旧入口始终保留旧协议，不用新版结果替代。

本轮取得的官方旧版登录同步 HTML 明确调用原生 App 桥接：`userStatus` → `checkSessionIsvalid` → `getUserInfo`；有原生 `JSESSIONID` 时先尝试 `/website/sso/sessionAPP?tokenStr=...&currentUrl=...`，失败后通过 `getYDRZToken({sourceId:'017018'})` 获取 Token 并调用 `/website/sso/netUniAPP?leadeonToken=...&currentUrl=...`。官方还包含 `checkUID` → `assertion` 的原生 UID 分支；本工具没有原生桥接能力，不伪造 `checkUID` 结果。

后端现在支持 `sessionAPP` 及 `netUniAPP`，只有响应 `status === true` 才认为单点受理，再次打开固定旧版页面核对号码、状态和 CSRF。忽略上游 `returnUrl`，不向任意地址转发凭据。旧版页面仍不可用时返回 `LEGACY_APP_LOGIN_REQUIRED`（409），保留当前页并通过标准消息组件说明缺少的凭据。403/其他 HTTP 错误、身份不符、未登录分别处理，不再统称登录失效。

页面“导入 CK 查询”允许输入有效旧版 CK、原生 App CK，或由 `getYDRZToken` 获取的单点 Token。支持直接粘贴 CK、带 `Cookie:` 前缀的请求头，以及按行排列的 Cookie 键值；拒绝混入其他 HTTP 请求头。对应 prepare 请求的可选字段为 `legacyCookie` / `appToken`，只用于所选账号的独立会话，必须通过号码校验；不覆盖账号的云盘、wx10086 或 CMCC 凭据，不写本地存储，提交后清空输入框。自动维护不会先把导入的旧版 CK 置换成其他渠道 CK。

账号登录态无法建立旧版会话时，自动展开导入区，点击“导入 CK 并查询”即可尝试旧版接口。查询成功后可在原退订权限内发送验证码和确认退订，后续刷新及退订操作均使用同一导入会话。导入会话过期时，“重新导入 CK”只打开输入区，不悄悄改用站内 CK；如需切换，可明确点击“使用账号登录态查询”。更换凭据时立即停用旧会话操作，避免把导入失败后的旧结果误当成新会话。

查询需为当前用户关联账号或管理员可访问的账号；发送短信与退订复用现有 `businessQuery`（业务退订/撤回）权限，每次操作重新校验。不新增默认放开的退订权限。禁用账号、跨账号会话及伪造业务 ID 均拒绝。

## 官方接口与协议

域名 `wx.10086.cn`，路径前缀 `/website/alreadyService/`。

| 接口 | 方法与参数 | 处理 |
| --- | --- | --- |
| `queryAllBusiTabCfg` | GET，`istype=1`、时间戳 `t` | 解密配置；`status=0000` 且 `close=1` 表示关闭入口 |
| `queryAllBusiZ` | POST JSON：`queryType` | `01` 我的套餐、`02` 增值业务、`03` 基础服务、`04` 活动；海南按官方页面不查询活动分类 |
| `queryAllBusi` | GET：`queryType`、时间戳 `t` | 当配置返回 `data` 分类数组时按官方旧分支查询，列表与 `oprTime` 在响应根节点，不能硬套四分类 POST |
| `cancelPreCheck` | POST，原业务标识 | 云南、河南、西藏在发送短信前校验；`checkResult=Y` 才继续，其他情况提示官方客服办理 |
| `contractSendCode` | POST：`prodName`、`prodCode` | `prodCode` 缺失时，按官方代码使用 `spId + bizCode` |
| `testToUnsubscribe` | POST，见下文 | 名称含 test，但抓包证实这是**实际退订接口**，不是沙箱 |

请求使用当前旧版页面的 `csrf-token`、原页面 Referer 和 Cookie。POST 使用 `Lrsbhbg8` 协议标识及动态 `e76ccba5165fa9b4966ad82a0088e520` 请求 ID；配置及旧 GET 查询按源码 `12cf` 封装，不附加这两个 POST 封装字段。响应开启 `Lrsbhbg8: true`、`needdecrypt: true` 或返回十六进制密文时，用现有 `cmccCrypto` AES-CBC/PKCS7 解密。请求 ID 与响应 `id`（如有）核对一致。HTML、403、解密错误不能视为业务成功。

查询外层 `status=0`，列表在 `data.busiList`，时间在 `data.oprTime`。列表保留业务原始字段于服务端，前端只接收展示字段与不可猜测的业务 ID。四个分类依次查询，某个分类失败不清除其他分类或该分类之前成功的结果。

退订参数从服务器查询结果取得，不允许客户端覆盖：

| 参数 | 来源/含义 |
| --- | --- |
| `prodCode` / `prodName` | 业务编码/名称 |
| `bizCode` / `spId` | 第三方业务/服务提供方标识，保留空字符串与原值 |
| `codeType` / `interfaceName` | 业务接口分类与路由，例如样例 `01` / `ZT`，不固定写死 |
| `isSPBusi` / `prodInstId` | 查询结果存在该字段才发送；不会把 `InstanceId` 擅自改名为 `prodInstId` |
| `prodType` | 原字段，未返回时发送空字符串 |
| `passWordType` | 官方短信验证码模式 `02`，注意字段大小写 |
| `password` | 6 位短信验证码按现有 AES 加密后传入，原始验证码不记录日志 |

外层成功不等于发送/退订成功：短信需 `data.status=0`；`6003` 为获取过多，`6005` 为验证码有误。退订还必须收到 `data.data.retCode="0"`，`retMsg` 展示业务结果，`cancleTime`（官方拼写）展示退订时间。没有明确成功结果时，不显示成功、不移除业务、不自动重试副作用请求。

## 页面行为

Public 账号菜单、用户管理、账号工具箱及新版业务查询页提供“旧版已订业务”入口。支持全部/分类查看、名称与编码搜索、资费/日期/业务详情。返回链接保留来源与专属链接上下文，限定站内路径。

旧版普通业务按钮遵循 `canUnsub=1`、非主套餐、非合约、非已退订与用户退订权限。合约的独立退订协议不在本次抓包范围，不把普通业务短信参数套用于合约；现有合约查询/退订功能保留。

退订前展示号码和业务并要求确认。发送成功后倒计时 60 秒，关闭重开弹窗不重置倒计时；服务端按账号与业务限制重复发送。发送失败和验证码错误可重新操作。服务端按账号串行互斥，防止跨标签页同时提交。页面会话过期可“重新准备登录态”，不会自动重新提交退订。
