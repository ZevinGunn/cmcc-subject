# CMCC 项目代码库

围绕中国移动、全球通及北京电信业务整理的多项目工作区，包含账号与登录态管理、业务查询和订购、权益活动、资料检索、日常工具、跨平台客户端及服务运维。

各目录是用途不同的独立工程，并非一个统一启动的应用。本文按现有源码入口、页面和项目文档介绍已实现的能力；接口已经实现不等于所有业务都已完成真实线上验收，实际受理仍取决于官方接口、账号资格和当次验证结果。离线模拟器与本地原型在下文单独标明。

## 综合平台、客户端与日常工具

### 免登录进入全球通/cookie-app：移动账号与全球通综合工作台

这是本工作区的综合账号平台，用于集中维护移动账号、登录凭据、访问权限和业务操作入口。

- 维护账号登录态，支持登录、凭据导入、Cookie/Token 刷新和批量任务；主存储使用 PostgreSQL + Prisma，敏感字段通过 AES-256-GCM 加密。
- 提供管理员、用户、公共专属链接、账号授权及访问日志管理，区分后台管理入口与公共使用入口。
- 接入移动业务查询、商城查询、旧版已订业务查询与退订，并提供独立的业务订购工作台。
- 包含全球通合约、北京移动活动、COC 权益、爱购、宽带及客服预约等业务接口和对应操作流程。
- 集成全球通日常任务、幸运三日签、周三拼图、星巴克账号与卡券等活动模块。

前端为 React + Vite + TypeScript，后端为 Express + TypeScript。具体权限、配置、发布和业务接入范围以[项目说明](免登录进入全球通/cookie-app/README.md)及其 `docs/` 为准。

**附属工程 `cookie-app/go-worker`**：可选的 Go 批量刷新执行器，提供 Cookie 刷新、Token 刷新及两者串联的任务接口，并可配置并发数、请求间隔和超时。它依赖主服务，不是另一套账号管理平台，见 [Go Worker 说明](免登录进入全球通/cookie-app/go-worker/README.md)。

**父目录 `免登录进入全球通/`**：还保留早期登录流程说明、自动刷新 CK 和全球通签到 Python 脚本，便于追溯协议与工程演进。综合管理功能应从 `cookie-app/` 开始阅读；父目录中的抓包和网页样本属于本地参考资料。

### project-manager：Project Ops 服务运维后台

为工作区中的应用提供统一运维入口，不承担运营商账号的业务办理。

- 通过 `services.json` 管理服务清单、PM2 名称、端口、域名、支持的操作和发布命令。
- 分别检查进程、监听端口、应用健康、公网响应与前端产物，定位“进程在线但页面不可用”等问题。
- 按服务执行启停、重启、测试、构建和发布，并通过异步操作任务、互斥锁与操作日志追踪执行过程。
- 提供隔离构建、产物切换、发布后检查和失败恢复机制，以及日志、缓存、备份等存储管理能力。
- 保留传统 `/home` 页面与 `/v2` 运维界面，并提供 `ops-cli.js` 命令行入口。

技术栈为 Node.js 内置 HTTP 服务与原生前端，详见[独立说明](project-manager/README.md)。

### service-clients：随行工具箱客户端

把各个现有工具站点集中到统一客户端入口，同时保留服务端各自的业务逻辑和登录体系。

- Electron 桌面端提供分类、搜索、工具切换、前进返回、下载、站点登录和清除登录状态等能力。
- Android 原生 WebView 端提供工具选择、页面导航、文件选择和外部链接跳转。
- 桌面与安卓共用服务目录，直接访问已有 HTTPS 服务，不在客户端重新实现账号数据库或订购后端。
- `miniprogram/` 是独立的微信原生小程序工程，包含站点登录、移动账号摘要、权限查询、星巴克短信登录及卡券筛选/复制。
- 提供桌面与安卓构建、图标生成和客户端检查脚本；小程序的真实 AppID、真机联调及平台发布需要另外配置。

工程和平台差异见[客户端说明](service-clients/README.md)，工具目录见[服务入口](service-clients/SERVICES.md)。

### tools-workbench：浏览器工具工作台

提供与运营商账号无关的日常文本、链接和二维码处理工具。

- 拼接统一前缀、查询参数和后缀，并生成二维码。
- 摄像头连续扫码、多图片批量解码，支持记录命名、去重和 CSV 导出。
- 逐行批量生成二维码，可配置题注、图标、颜色及点阵样式。
- 提供 AES 口令加解密、URL 编解码、JSON 格式化/压缩/解转义及 QX URL 正则生成。

使用 React + Vite；工具中的文本、图片、密钥与扫码记录在浏览器本地处理。详见[项目说明](tools-workbench/README.md)。

## 地区业务与权益办理

### bj-mobile-business-local：北京移动业务查询、退订与快捷订购

围绕北京移动门户和商城提供独立业务工作台。

- 短信登录后查询门户已订业务，按基础功能、套餐和增值业务分类展示，并对支持的业务发起退订。
- 使用商城登录 Cookie 查询 `shop.10086.cn` 已订业务，按其短信验证链完成退订。
- 读取活动配置，执行资格查询、办理预览、自定义业务参数填写和短信确认。
- 统一快捷订购入口适配 xyw.bj、北京移动门户、移动商城、网格通及家庭云电脑等不同协议。
- 提供 AES 模式、IV、编码设置及 HAR/JSON/TXT 参数导入等本地协议调试工具。

使用 Vue + Vite + Express。各平台流程独立适配，并非只替换一个商品编码即可通用，详见[项目说明](bj-mobile-business-local/README.md)。

### bj-cmcc-qy：北京移动权益一条龙

面向北京移动权益平台，集中处理 Plus 券、权益兑换与订单查询。

- 短信发送、验证码登录、Plus 券数量查询。
- 权益列表与详情、Plus 纯享包本地清单。
- 兑换前补齐权益、券及商品关联参数，预览后由用户确认提交。
- 查询兑换订单列表与订单详情，并保留协议调用调试入口。
- 封装上游 AES-CBC 加密、SHA-256 签名及响应解析。

使用 Vue + Vite + Node.js，详见[已实现功能](bj-cmcc-qy/README.md)。

### bjcmcc-route-hub：北京移动业务与权益快捷入口

用于查找官方页面地址，与真正办理业务的工作台分工不同。

- 从北京移动业务及权益前端 bundle 解析页面目录，分别处理 History 和 Hash 路由。
- 提供关键词搜索、收藏、关联页面查看和微信免登录入口。
- 两类目录分别支持增量导入、版本历史与回滚快照。
- 使用可维护的种子目录保存入口资料。

使用 Vue + Node.js，详见[项目说明](bjcmcc-route-hub/README.md)。

### coc-rights-order-local：COC 权益订购工具

针对 COC 权益商品提供单次订购操作界面。

- 输入权益 `code` 或 `skuId`，解析商品并查询 SKU 类型。
- 输入手机号、发送短信、提交验证码。
- 展示结果并在明确确认后调用订购接口。
- 保留 `operDfp` 等协议参数的适配入口。

使用 Vue 3 + Node.js，详见[项目说明](coc-rights-order-local/README.md)。它聚焦 COC 协议，不替代北京移动门户、王卡或山西移动的订购流程。

### ct189-local：北京电信快捷服务

提供北京电信账号、服务密码登录、会话维护和权益任务管理。

- 添加、导入、备注、分组、启停和删除账号，按号码、分组与登录状态筛选。
- 通过无头浏览器执行官网服务密码登录，核对账号身份后加密保存密码，并按会话状态自动补登。
- 查询账号资料、活动资格及余额相关结果；部分查询失败时保留已经取得的数据。
- 提供权益领取策略、立即执行与定时计划，可配置预热、间隔、尝试次数、并发数和执行器。
- 支持 Node 内置及 Python、JavaScript、Go、Java 外部执行器，并检测运行环境是否可用。

网页版使用 Vue + Node.js/Playwright；`qinglong/` 是独立 Python 工程，当前支持登录与只读活动资格查询，不能把网页版能力直接当作青龙脚本能力。详见[网页版说明](ct189-local/README.md)和[青龙说明](ct189-local/qinglong/README.md)。

### shanxi-order-local：晋速办

山西移动的多账号业务操作台，包含登录、订购、查询、退订和协议工具。

- 短信验证码登录、官方窗口登录、账号切换与加密会话缓存恢复。
- 内置全球通 5G-A 业务配置，并支持新增、复制、修改和删除自定义业务配置。
- 查询业务内容与资格，区分登录短信和业务短信，完成普通/敏感业务校验、确认订购及结果核查。
- 分类查询已订业务，展示官方字段，发起退订并保存、导出办理记录。
- 提供入参与响应加解密、RSA 公钥包装和 HMAC 签名校验工具；记录待核查状态以阻止结果不明时重复提交。

使用 Node.js + Playwright + Vite。缺少真实协议参数的业务草稿仍属于待补全配置，不能直接办理；已实现流程与线上验收边界见[项目说明](shanxi-order-local/README.md)。

### wangka-order-local：王卡会员便捷订购工具

针对普通王卡会员与超级会员青春版组织独立的查询和订购流程。

- 查询普通王卡会员状态及青春版套餐。
- 按各自协议发送短信、校验验证码并提交入会或订购。
- 提供 HAR/mock 流程测试，页面及响应对号码、验证码票据等内容脱敏。
- 默认使用 mock 模式；真实模式需单独开启并提供当次合法会话和验证资料。

使用 Python HTTP 服务与原生网页。GitHub 源码快照不携带 HAR，mock 演示需自行准备项目说明要求的本地样例。详见[项目说明](wangka-order-local/README.md)。

### migu-quick-order：咪咕业务快速订购原型

以咪咕视频会员年包合约为默认配置，提供 xyw.bj 营销业务的本地操作页面。

- 查询页面/活动状态、商品信息与订购确认内容。
- 分别执行登录短信、验证码登录、订购短信和最终确认订购。
- 在页面维护多个业务配置，结果保存在 `config/products.json`。
- 提供会话重置、网络诊断、RSA 入参加密及返回内容解析工具。

使用 Python 标准库 HTTP 服务与原生 JavaScript。这是本地调试原型，当前实现的访问控制及上游 TLS 校验不适合直接公网部署。入口、端口和流程见[独立说明](migu-quick-order/README.md)。

## 全球通活动、任务与监控

### qqt：全球通短信登录与权益代理

使用本地后端封装全球通网站请求，前端展示登录状态与权益操作。

- 发送短信、验证码登录、手动导入 Token 和退出登录。
- 查询用户资料、权益商品及家庭成员信息。
- 提交普通权益兑换与星动日兑换请求。
- 将请求签名、加解密、上游调用及前端展示分离。

使用 Vue 3 + Vite + Node.js，详见[项目说明](qqt/README.md)。

### qqt/qqt-cmicrwx：全球通独立子工程

与 `qqt/` 主工程同类，但保留独立的 `package.json`、`backend/` 与 `frontend/`。

- 实现短信登录、Token 导入、用户资料与退出登录。
- 实现商品列表、普通权益兑换、星动日兑换和家庭成员查询。
- 可以单独安装依赖并启动，便于对照和维护同类协议实现。

这是嵌套项目，不是 `qqtlocal-rights` 抢购调度服务；源码入口为 [`backend/src/index.js`](qqt/qqt-cmicrwx/backend/src/index.js)。

### qqtlocal-rights：全球通权益抢购与任务调度助手

把权益操作组织为可配置、可定时执行的任务。

- 管理账号 Cookie、活动类型、商品、开始时间、执行轮次、间隔和并发策略。
- 支持立即运行、计划调度、任务持久化、执行日志及结果摘要。
- 具备 Python、Go、Java 执行器；实际吞吐量取决于本机、网络与上游限制，本文不沿用未经测量的并发性能保证。
- 适配普通权益、星动日及周三充值等活动逻辑。
- 提供授权密钥、管理员入口、pushplus 通知，以及与 cookie-app 的凭据同步和结果回写接口。

使用 Python FastAPI、调度器与多语言 worker，详见[项目说明](qqtlocal-rights/README.md)及[开发文档](qqtlocal-rights/docs/development.md)。

### wed-puzzle-toolbox：周三拼图互助工具箱

围绕周三活动的多账号拼图库存和转赠流程提供专用工具。

- 手机号验证码登录、App 凭据/活动 CK 导入，以及从 cookie-app 导入有权限的账号。
- 查询三档拼图库存，按缺口规划互赠并逐张接收、核验库存变化。
- 提供号池接力、外部赠送链接接收、满足条件时抽图和每日任务执行。
- 对操作采用串行控制、执行进度、检查点与中断恢复，避免把重复请求当作新任务。

使用 TypeScript + Vite + Node.js，详见[项目说明](wed-puzzle-toolbox/README.md)。抽图策略不是官方必中奖承诺，仍以实际库存和上游结果为准。

### starbucks-price-monitor：星巴克券回收价监控

监控星巴克 30 元券的回收报价，并在达到配置条件时通知接收人；它不负责出售或核销卡券。

- `arpu.html` 提供北京移动 ARPU 消费查询、号码导入/待查询队列及消费计算器。
- `productSearch.html` 内置二类合约资料，可按关键词、分类、编码前缀、有效期及资料完整性筛选。
- `proxy-server.js` 与 `proxy-server2.js` 分别为两个页面提供静态文件及上游代理。

### contract3-query：北京移动合约统一查询

把二类、三类合约与低消方案等级整理成统一的只读资料检索服务。

- 按合约类型、关键词、编码前缀、分类及全球通等级查询和分页。
- 展示方案名称、编码、资费、期限和有效期等已有资料。
- 导出当前查询结果为 CSV。
- 提供导入脚本，从对应 HTML、Excel 和 Word 来源重新生成静态 JSON 目录。

使用 Node.js HTTP 服务与原生网页。源码快照包含已整理的目录数据；更新目录时需自行准备未上传的原始资料。详见[项目说明](contract3-query/README.md)。

### 云盘/yunpan-login-local：云盘登录与业务 SSO 工作台

用于调试中国移动云盘主会话，以及云盘到其他业务的单点登录链路。

- 获取 RSA 公钥、处理官方滑块/短信验证、登录并保存主会话 Token。
- 按目标业务现场申请 SSO 票据，生成 10086、全球通、云手机及自定义业务跳转链接。
- 跟随上游认证与重定向收集实际下发的 10086 Cookie，并提供全球通登录验证流程。
- 区分缓存结果和实时换票结果，提供会话恢复及按请求 ID 关联的脱敏诊断日志。

使用 Node.js 与原生网页，部分 SSO 验证使用浏览器执行官方页面。不同业务的票据不可互换，详见[项目说明](云盘/yunpan-login-local/README.md)。

## 如何开始阅读和运行

1. 根据上方导航选择项目，先读对应 README，再进入页面入口、API 路由与服务模块。
2. 各项目独立安装依赖和启动；根目录没有统一的 `npm install` 或“一条命令启动全部业务”的约定。
3. Vue/React 项目通常分前后端，Python 项目、静态查询工具及客户端工程的环境要求不同，使用各自声明的运行版本和命令。
4. 本地 `.env`、账号库、会话、浏览器缓存和推送令牌不包含在源码快照中。配置应从项目模板准备；必要的商品、合约和路由种子目录则属于源码资料。
5. 需要真实上游的项目由用户完成当次登录和业务确认；离线模拟器只演示流程。本文整理不代表对短信、订购、退订、领奖或交易执行了新的线上测试。

## Git 保存与维护

- 根目录 `.gitignore` 排除 HAR、ZIP 等原始归档，以及依赖、构建产物、日志、敏感环境配置和临时文件。
- 当前 GitHub `main` 是整理后的源码快照，包含嵌套项目的实际文件；本地原有独立仓库和旧提交历史另行保留，不能把含敏感历史的原分支直接推送到源码快照分支。
- 项目功能、目录或运行方式发生变化时，同步更新本导航及对应项目 README。
- 纯文档更新只保存和同步 Git，不构建或重启业务服务。运行代码的验证与发布要求见 [AGENTS.md](AGENTS.md)。
