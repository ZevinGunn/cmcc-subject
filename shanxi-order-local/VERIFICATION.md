# 验证记录

日期：2026-10-17；版本：1.1.0。

## 已验证

- 42 项 Node 测试：原订购状态机、Host/Origin/CSRF、手机号/协议校验、登录挑战过期与次数限制、验证码前导零、号码一致性、发码丢包与冷却、敏感验证码、撤销失效验证、查询脱敏、超时/重启恢复、重复订购拦截；新增官方 SDK 环境头传输、环境失败不发送、通道诊断隐私限制。
- 加密协议测试：官方十六进制 DER 与 PEM 公钥、PKCS#1 填充检查、独立模拟服务解密与 HMAC 校验、每请求随机密钥和 IV、响应解密和损坏拒绝、只读入口发现与写请求不重试。
- Vite 生产构建。
- 自动离线浏览器流程：错误登录验证码→正确登录→查询业务内容→获取敏感短信→校验→确认订购→办理记录→已订业务；1440 像素桌面与 390 像素手机登录弹窗，无横向溢出或浏览器运行异常。
- 官方实时只读检查（新建无账号会话）：公钥返回 0000；登录检查解密得到 777777 / 未查到用户登录信息；资格查询解密得到 999999 / 用户未登录。act 入口 HTTP 400 时，只读发现阶段选用同源 market 入口。

2026-10-17 18:44（北京时间）起，在用户明确授权后测试登录发码。先前会话请求返回结果不确定；重建独立浏览器会话后，登录发码接口返回 `0000 / OK`，本地接口 HTTP 200。**用户随后明确反馈没有收到任何验证码，端到端发码验收未通过。** 手机号未写入源代码或记录文档；没有完成真实验证码登录，不能把接口受理当作短信送达。

后续查证：当前官方静态 HTML、JS 在本机网络下返回 HTTP 400 空白响应，独立手机 UA 结果相同；官网 SDK 因此未加载。适配原先缺少 `Content-M-CODE`，且登录标题与 `/loginSim` 路由元信息不同。已按源码补齐真实 SDK 环境头并修正标题，同时增加有限通道状态诊断；这些差异尚不足以确定未送达的原因。页面提示改为官方受理请求，等待手机实际收到。

22:40:34（北京时间），上述修正已构建并重启本机服务后，在同一新建会话先执行只读登录检查，再向用户授权的号码请求一次登录短信。环境诊断 `sdk=true, telemetry=false`；官方响应 `0000 / OK`，通道字段 `NET_FLAG=Y, SEND_TYPE=UA, NET_TYPE=CMCC`。**用户确认这一次短信已收到。** 因同时修正了环境头与标题，未单独隔离哪一项造成之前未送达；不根据未公开的通道字段推断下发规则。尚待当次验证码完成登录与已登录查询；服务保持会话，没有继续重复发码。

官网登录表单在当前网络环境仍可能空白；签名适配不再依赖表单或 Vue 加载完成。已订业务页面采集仍依赖官方页面，不能把离线列表通过视为官方列表已验收。其他业务商品未纳入当前订购白名单。

## 复现

运行 `npm run check` 和 `npm run test:ui`。后者启动并清理独立离线测试服务，输出截图临时目录；正式入口不载入测试适配器。运行服务版本可在 `/api/health` 检查。此项目仅本机监听，没有已配置的公网部署。
