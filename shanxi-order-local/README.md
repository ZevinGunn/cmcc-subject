# 晋速办 1.8.0

独立公网地址：[山西移动业务订购](https://shanxi.1008086.xyz/)，直接使用移动短信登录。Project Ops 仅用于服务维护；不同浏览器的移动缓存、业务配置与记录独立保存；完整部署与访问说明见 [PUBLIC_DEPLOYMENT.md](PUBLIC_DEPLOYMENT.md)。以下本机使用方式继续支持。

山西移动本地业务操作台，地址 **http://127.0.0.1:4318**。内置**全球通 5G-A 加速权益 BCAT5075**，支持保存多个自定义业务配置，以及登录短信、验证码登录、业务内容/资格查询、普通或敏感业务短信验证、确认订购和结果核查。

页面使用用户提供的山西移动图标作为主题 Logo、PNG/ICO favicon 与 Apple touch icon，采用蓝绿渐变背景和顶部导航。业务条款、资格结果、验证码和最终确认保持独立呈现；未登录时可直接从业务卡片打开登录框。

## 使用

双击 `启动晋速办.command`，或执行 `node scripts/start.mjs`。

1. 点击“验证码登录”，填写手机号，阅读服务协议与隐私政策后获取登录短信。
2. 输入当次 6 位登录验证码。登录后在号码卡片中查看脱敏号码、登录状态与官方返回的归属地、号码状态、品牌、入网时间及主套餐等资料；未返回的字段不展示。
3. 从号码卡片的“功能菜单 → 业务办理”进入，在“当前业务”选择已保存的业务，点击“查询业务内容”，查看资费、产品编码、条件、官方资格结果及查询时间。
4. 符合资格时点击“办理此权益”；提示“已默认享有”或“已办理”时，也可点击“仍尝试办理”。在弹窗中获取业务短信，敏感验证码由官方返回两位固定数字与位置，本地补齐后提交验证。
5. 核对号码、当前业务的配置资费和使用条件，勾选确认后提交。结果在“办理记录”中保存。

登录失败可选择“官方窗口登录”，完成后点击“同步官方登录”。官方窗口即使没有加载 Vue 登录表单，签名请求适配仍可独立工作；若官网要求人工验证，请在窗口完成。验证码和订购请求不自动重试。

1.7.1 修复 act 公钥入口 HTTP 400 导致查询失败的问题，先通过只读探测选择可用入口；公网保留上游错误的 JSON 原因。

“已订业务”直接查询官方接口，按套餐、待生效套餐、活动、增值业务和基础功能展示，支持搜索及套餐详情。所有已订业务均展示尝试退订入口，不因套餐、基础功能或缺少 UnSubScribe 标记而拦截；官方可能拒绝受理。选择业务、重新核对、查看完整退订参数并勾选确认后提交。缺失或非法产品编码无法提交。退订不套用订购短信步骤；超时结果会保存并拦截重复提交，核实未生效后可人工解除。活动查询失败保留其他业务与旧活动，各业务条目直接展示官方返回的全部非空业务字段，含零值、布尔值、嵌套字段与外层元数据；凭据过滤和号码脱敏继续生效。退订记录与订购记录分组展示在当前号码的“办理记录”，可导出。协议与恢复机制见 [查询与退订说明](SUBSCRIPTIONS.md)。

## 入参与响应加解密

进入“加解密工具”，选择“请求入参 / 响应值”及“加密 / 解密”。本机与独立公网版均可使用，无需移动账号登录。

- 加密：输入 JSON 明文和 16 位可打印 ASCII 的 AES 密钥。入参加密可留空自动生成密钥；响应加密应使用对应请求的密钥。
- 解密：输入完整的 `encryptInStr` / `encryptOutStr` JSON、纯十六进制密文，或含 `body`、`headers` 的请求包装，并填写原请求 AES 密钥。提供 `E-T-K`、`E-S-K` 时同时校验 HMAC 签名，篡改或不匹配会明确报错。`secretOutId = -1` 的响应直接解析，无需密钥。
- 可选 RSA 公钥：支持 PEM、SPKI DER 十六进制和 Base64；填写后入参加密同时生成 `E-A-K`、`E-T-K`、`E-S-K`。公钥留空只生成入参密文，不表示已具备可提交的完整官方请求。
- 支持 JSON 格式化、复制结果/密钥/请求头/完整请求、结果作为输入，以及清空内容。修改输入后旧结果失效，切换页面保留本页内容，刷新清空。

协议为 AES-128-CBC / PKCS#7、IV 前置十六进制，密钥包装为 RSA PKCS#1 v1.5，签名为 HMAC-SHA256。`E-A-K` 本身不是 AES 明文密钥，**仅凭官方 RSA 公钥与抓包内容无法还原密钥**。工具不会导出账号会话或缓存真实业务报文。

计算由当前服务完成，输入、密钥、输出不写入账号缓存、订单、日志或浏览器持久存储，不发送至移动接口。单次明文上限 16 KiB、输入上限 48 KiB，JSON HTTP 请求整体上限 64 KiB。工具生成报文不发起订购，现有验证码与确认流程继续独立生效。

## 多账号与登录缓存

顶部账号选择框可切换账号，右侧“账号管理”图标可进入管理页，添加账号、修改备注、校验缓存和移除账号。最多保存 50 个账号，各账号使用独立官方浏览器上下文、验证码流程和本机订单视图；切换时关闭闲置官方窗口，保留会话缓存。

登录成功后自动保存加密缓存；重启程序会恢复上次选择的账号并校验官方身份。输入已缓存号码时，先校验缓存：有效则直接恢复，不发登录短信；官方明确失效或身份不符后才允许重新登录。网络异常/人工验证要求不会清空缓存或触发重登，可点击“重试恢复”。有效期由官方决定，不设虚构的固定有效时长。

主动“退出登录”会清除当前账号的本机缓存，之后可重新登录；移除账号还会删除其备注和账号条目。两者均不删除历史订单或其他账号。这里的退出仅清除本机状态，不宣称使其他设备上的官方会话失效。

账号切换后旧业务验证码撤销；业务请求携带账号 ID 与选择版本，旧浏览器标签页不能向另一个账号发码或下单。业务配置全账号共用，订单与重复订购保护仍按账号、产品隔离。

## 自定义业务配置

已根据“山西移动业务订购部分记录.har”新增“科技工作者日专属权益”和“咪咕体育”两项**待补全配置**，现有工作空间升级后自动增补并保留原选择和修改。该 HAR 未导出响应正文，业务请求仅有密文，不能恢复具体套餐编码、短信类型、资费及完整订购参数；已确认字段和缺失项见 [业务来源记录](CAPTURED_BUSINESSES.md)。这两项尚不能直接办理。

待补全配置可继续修改保存；补齐真实参数和资费后，取消“配置待补全”并保存才启用查询、验证码与订购。页面、账号服务和协议均阻止草稿发起业务请求，已有完整业务的“仍尝试办理”流程继续支持。删除过的预置项不会重启复活，已编辑项不会被预置覆盖。

进入“业务配置”可修改现有配置、新增、复制、删除，并切换当前业务。支持：

- 展示信息：名称、资费、有效期、说明、使用条件。
- 短信参数：busiType、prcId、busiId、actId、actType、meansId、busiName、prodDesc、effDate、channelId、sendType、businessCode。
- 请求配置：act/market 入口、couponsBusiName、订购相对路径与额外 JSON、查询模式、相对路径与 JSON。

表单 * 是本地流程必填项，目标业务另有的必填参数填入订购 JSON。uuid、短信验证码、敏感验证标记由当次流程自动提供，不能写入配置；订购 busiType 统一使用短信配置。登录接口和官方主机固定。新增业务需明确填写自己的订购路径，不预填 5G-A 接口。

“保存配置”只保存。“保存并尝试订购”保存后打开确认弹窗；仍需用户获取短信、校验并确认才会发出订单。修改或切换配置会使旧验证码失效，旧页面发码也会检查配置版本。相同产品复制或改名不解除重复保护；订单核查使用下单时的配置快照。

配置保存到 `.local/business-configs.json`，重启仍保留；最多 100 项。请勿在配置中填写账号凭据或个人数据。

## 范围与验证边界

内置 BCAT5075 保留专用资格解释；自定义业务复用同源加密协议和 smsver 验证链，查询与订购路径、参数可配置。附件 HAR 的业务请求体为加密内容，不能据此断言任意商品的全部必填参数。更换产品编码时必须同时核对目标业务的订购接口和参数；仅修改 prcId 不能证明另一个业务可受理。不同协议、额外验证或退订流程仍需要单独适配。

通用查询展示官方响应而不套用 5G-A 资格码；未配置查询时标为未核实。两者均需主动选择“仍尝试办理”，再完成业务短信与最终确认。“已默认享有/已办理”也保留尝试入口；本机成功、待核查等记录的同产品重复保护仍然有效，原 5G-A 明确过期/无资格状态仍拦截。配置资费是用户填写的说明，不代表官方报价。

2026-10-17 已验证官方实时公钥、签名请求及响应解密：新建空会话的登录检查返回 `777777 / 未查到用户登录信息`，资格查询返回 `999999 / 用户未登录`。未复用 HAR 中的账号、Cookie 或验证码。最初实测登录短信接口返回 `0000 / OK`，但用户未收到；对齐官方 SDK 环境头与登录路由标题后，22:40:34（北京时间）再次请求，用户确认此次短信已收到。随后使用用户当次提供的验证码登录，官方身份检查返回 `0000 / OK`，号码与本轮输入一致；业务资格查询返回 `900005 / 本权益您已默认享有，无需办理`。**真实登录短信到达、验证码登录与已登录资格查询已验证。** 未发送业务订购短信或真实订购，已订业务列表与订购链路仍未完成线上验收。

离线测试覆盖完整登录到订购闭环和异常状态，详见 `VERIFICATION.md`。官网维护、业务资格或环境验证可能使真实操作被拒绝，界面显示官方结果，不伪造成功。

## 运行与隐私

需要 Node.js 20+ 以及 Chrome；没有 Chrome 时执行 `npx playwright install chromium`。首次安装运行 `npm ci && npm run build`，再执行 `npm start`。仅监听 127.0.0.1，没有公网服务映射。

各账号的号码与必要登录状态（Cookie、官方域 localStorage/sessionStorage/IndexedDB）按 AES-256-GCM 加密存入 `.local/accounts.enc`，密钥在本机 `.local/session-key`；文件仅当前用户可读写。密钥与密文同机保存用于防止意外明文泄露，不替代操作系统访问保护。登录/业务验证码、短信 UUID 和本地挑战不写入账号缓存；已知验证码存储字段导出时排除。缓存写入失败会明确提示，不能把尚未保存的内存会话当作可重启恢复。

订单文件保存脱敏号码、业务名称、结果、本地记录号及当次非身份业务配置快照。`.local/` 全部属于私人运行数据，不应提交或分享。迁移订单需同时保留 `account-key` 与 `orders.json`；迁移账号缓存需同时保留 `accounts.enc` 与 `session-key`。缓存损坏或缺少密钥会保留文件并报错，不静默清空。

提交前持久化订购意图；响应丢失或服务中断后显示“结果待核查”，不会自动再订。先核查权益，只有向官方确认原请求未生效后才手动解除拦截。
