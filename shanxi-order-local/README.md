# 晋速办 1.2

山西移动本地业务操作台，地址 **http://127.0.0.1:4318**。内置**全球通 5G-A 加速权益 BCAT5075**，支持保存多个自定义业务配置，以及登录短信、验证码登录、业务内容/资格查询、普通或敏感业务短信验证、确认订购和结果核查。

页面使用用户提供的山西移动图标作为主题 Logo、PNG/ICO favicon 与 Apple touch icon，采用蓝绿渐变背景和顶部导航。业务条款、资格结果、验证码和最终确认保持独立呈现；未登录时可直接从业务卡片打开登录框。

## 使用

双击 `启动晋速办.command`，或执行 `node scripts/start.mjs`。

1. 点击“验证码登录”，填写手机号，阅读服务协议与隐私政策后获取登录短信。
2. 输入当次 6 位登录验证码。登录成功后展示脱敏号码。
3. 在“当前业务”选择已保存的业务，点击“查询业务内容”，查看资费、产品编码、条件、官方资格结果及查询时间。
4. 符合资格时点击“办理此权益”；提示“已默认享有”或“已办理”时，也可点击“仍尝试办理”。在弹窗中获取业务短信，敏感验证码由官方返回两位固定数字与位置，本地补齐后提交验证。
5. 核对号码、当前业务的配置资费和使用条件，勾选确认后提交。结果在“办理记录”中保存。

登录失败可选择“官方窗口登录”，完成后点击“同步官方登录”。官方窗口即使没有加载 Vue 登录表单，签名请求适配仍可独立工作；若官网要求人工验证，请在窗口完成。验证码和订购请求不自动重试。

“已订业务”继续使用官方 `/commserver/userBuss` 页面实际发出的查询，展示本次捕获的响应；其可用性依赖官方业务页面，不承诺覆盖所有分类与分页。业务内容查询与此列表是两个独立入口，失败不会清空已加载列表。

## 自定义业务配置

进入“业务配置”可修改现有配置、新增、复制、删除，并切换当前业务。支持：

- 展示信息：名称、资费、有效期、说明、使用条件。
- 短信参数：busiType、prcId、busiId、actId、actType、meansId、busiName、prodDesc、effDate、channelId、sendType、businessCode。
- 请求配置：act/market 入口、couponsBusiName、订购相对路径与额外 JSON、查询模式、相对路径与 JSON。

表单 * 是本地流程必填项，目标业务另有的必填参数填入订购 JSON。uuid、短信验证码、敏感验证标记由当次流程自动提供，不能写入配置；订购 busiType 统一使用短信配置。登录接口和官方主机固定。新增业务需明确填写自己的订购路径，不预填 5G-A 接口。

“保存配置”只保存。“保存并尝试订购”保存后打开确认弹窗；仍需用户获取短信、校验并确认才会发出订单。修改或切换配置会使旧验证码失效，旧页面发码也会检查配置版本。相同产品复制或改名不解除重复保护；订单核查使用下单时的配置快照。

配置保存到 `.local/business-configs.json`，重启仍保留；最多 100 项。请勿在配置中填写账号凭据或个人数据。

## 范围与验证边界

内置 BCAT5075 保留专用资格解释；自定义业务复用同源加密协议和 smsver 验证链，查询与订购路径、参数可配置。附件 HAR 的业务请求体为加密内容，不能据此断言任意商品的全部必填参数。更换产品编码时必须同时核对目标业务的订购接口和参数；仅修改 prcId 不能证明另一个业务可受理。不同协议、额外验证或退订流程仍需要单独适配。

通用查询展示官方响应而不套用 5G-A 资格码；未配置查询时标为未核实。两者均需主动选择“仍尝试办理”，再完成业务短信与最终确认。“已默认享有/已办理”也保留尝试入口；本机成功、待核查等记录的同产品重复保护仍然有效，原 5G-A 明确过期/无资格状态仍拦截。配置资费是用户填写的说明，不代表官方报价。

2026-10-17 已验证官方实时公钥、签名请求及响应解密：新建空会话的登录检查返回 `777777 / 未查到用户登录信息`，资格查询返回 `999999 / 用户未登录`。未复用 HAR 中的账号、Cookie 或验证码。最初实测登录短信接口返回 `0000 / OK`，但用户未收到；对齐官方 SDK 环境头与登录路由标题后，22:40:34（北京时间）再次请求，用户确认此次短信已收到。随后使用用户当次提供的验证码登录，官方身份检查返回 `0000 / OK`，号码与本轮输入一致；业务资格查询返回 `900005 / 本权益您已默认享有，无需办理`。**真实登录短信到达、验证码登录与已登录资格查询已验证。** 未发送业务订购短信或真实订购，已订业务列表与订购链路仍未完成线上验收。

离线测试覆盖完整登录到订购闭环和异常状态，详见 `VERIFICATION.md`。官网维护、业务资格或环境验证可能使真实操作被拒绝，界面显示官方结果，不伪造成功。

## 运行与隐私

需要 Node.js 20+ 以及 Chrome；没有 Chrome 时执行 `npx playwright install chromium`。首次安装运行 `npm ci && npm run build`，再执行 `npm start`。仅监听 127.0.0.1，没有公网服务映射。

浏览器使用独立临时上下文，关闭或退出即清除会话。登录短信、本地验证码挑战、原始号码、Cookie 和订购短信 UUID 只保存在内存；订单文件保存脱敏号码、业务名称、结果、本地记录号及当次非身份业务配置快照。`.local/account-key` 和 `.local/orders.json` 是运行数据，不应提交或分享。迁移记录时需同时保留二者，避免破坏重复订购保护。

提交前持久化订购意图；响应丢失或服务中断后显示“结果待核查”，不会自动再订。先核查权益，只有向官方确认原请求未生效后才手动解除拦截。

## 开发命令

- `npm run check`：单元/API 测试与生产构建。
- `npm run test:ui`：自动启动独立离线夹具，验证登录、订购、查询及桌面/手机界面；不会连接官方服务，截图保存在系统临时目录。
- `npm run dev`：前端开发；后端设置 `DEV_ORIGIN=http://127.0.0.1:5173` 后另行启动。
