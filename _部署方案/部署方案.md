# 六项目本地 Nginx 部署完整方案

> 目标：把 `~/CMCC-PROJECT` 下六个项目分别用本地 nginx 反向代理对外，主域名 `1008086.xyz` 下分配六个子域名。

| ---- | --------------------------------- | ------------------------------ | ------------------------------ | -------------------- | -------- | --------------------------------------- |

## 1. 打包总体思路（重要）

这六个项目里有三种不同形态，按形态决定打包/部署方式：

### 形态 A：前后端分离 SPA（Vite 打包出 dist，后端 Express/FastAPI 单独跑）
- `bj-cmcc-qy`、`qqt`、`免登录进入全球通/cookie-app`
- 部署：**前端 dist 由 nginx 直接托管静态文件；nginx 把 `/api` 反代到后端 Node/Express 端口**
- 这样可以避免「前端跑 vite dev、把 `/api` proxy 到后端」这种开发模式，生产更稳。

### 形态 B：后端自带静态托管（Express/FastAPI 直接 `express.static` 或 `StaticFiles`）
- `cmcc-notice`、`qqtlocal-rights`、`qqt（backend 也会托管 frontend/dist）`
- 部署：**nginx 直接 `proxy_pass` 到后端端口即可**，静态文件由后端服务自己出。

### 形态 C：HTML + 简易代理服务（无前端构建过程）
- `好礼多多本地版查询`
- 部署：**直接 `node proxy-server.js` 跑起来，nginx 反代到 :3000**，因为它自己同时处理静态与 /proxy 转发，结构不好拆。

## 2. 逐项目打包步骤

### 2.1 `home.1008086.xyz` → `免登录进入全球通/cookie-app`

> 这个项目最复杂：React + Express(TS) + Prisma + PostgreSQL。

**前置：PostgreSQL**

它依赖 PostgreSQL，可直接用项目里的 docker-compose（推荐）：

```bash
cd ~/CMCC-PROJECT/免登录进入全球通/cookie-app
# 1) 配置环境变量
cp .env.production.example .env.production
# 编辑 .env.production，把 ADMIN_KEY、CMCC_DB_ENCRYPTION_KEY、DATABASE_URL 替换为真实值
# DATABASE_URL 改为本机：postgresql://cmcc_user:CHANGE_ME_PASSWORD@127.0.0.1:5432/cmcc_cookie_app?schema=public
# 同时把 POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB 写到 .env

# 2) 启动数据库
docker compose up -d

# 3) 装依赖
pnpm install
# 或 npm install --legacy-peer-deps
```

**打包前端 + 后端 TS**

```bash
cd ~/CMCC-PROJECT/免登录进入全球通/cookie-app
# 生成 prisma client
npx prisma generate
# 迁移
npx prisma migrate deploy
# 构建前端（产物到 dist/）
npm run build
```

**启动后端（生产）**

后端是 TS，用 `tsx` 直接跑：

```bash

```

推荐用 pm2 守护，见 §4。

> 注意：`cookie-app/api/app.ts` 已经会自动 `express.static(distDir)`，所以本可以让后端自己出静态；但为了让 nginx 更高效缓存静态资源，我们用 nginx 单独托管 `dist`。

## 3. Nginx 完整配置

放在 `/opt/homebrew/etc/nginx/servers/cmcc.conf`（Apple Silicon Mac）或 `/usr/local/etc/nginx/servers/cmcc.conf`（Intel Mac）。

```nginx
# ============== 1. home.1008086.xyz （cookie-app） ==============
server {
    listen 80;
    server_name home.1008086.xyz;

    root /Users/你的用户名/CMCC-PROJECT/免登录进入全球通/cookie-app/dist;
    index index.html;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    client_max_body_size 25m;

    # SPA 路由 fallback
    location / {
        try_files $uri $uri/ /index.html;
    }
    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:3101;
    }
    location /debug/ {
        proxy_pass http://127.0.0.1:3101;
    }
    # 静态资源强缓存
    location ~* \.(?:js|css|woff2?|ttf|eot|svg|png|jpg|jpeg|gif|ico)$ {
        expires 30d;
        access_log off;
    }
}

# ============== 2. rights.1008086.xyz （bj-cmcc-qy） ==============
server {
    listen 80;
    server_name rights.1008086.xyz;

    root /Users/你的用户名/CMCC-PROJECT/bj-cmcc-qy/frontend/dist;
    index index.html;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    client_max_body_size 5m;

    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:3010;
    }
}

# ============== 3. arpu.1008086.xyz （好礼多多本地版查询） ==============
# 它的 Node 服务自己同时托管 HTML 和 /proxy/，直接整体反代
server {
    listen 80;
    server_name arpu.1008086.xyz;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;

    location / {
        proxy_pass http://127.0.0.1:3000;
    }
    # 可选：保留 productSearch.html
    # location = /productSearch.html { proxy_pass http://127.0.0.1:3001; }
    # location /proxy_ps/          { proxy_pass http://127.0.0.1:3001; }
}

# ============== 4. qqtlocal.1008086.xyz （qqtlocal-rights，FastAPI） ==============
server {
    listen 80;
    server_name qqtlocal.1008086.xyz;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:8899;
        # FastAPI WebSocket 支持（如有）
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

# ============== 5. notic.1008086.xyz （cmcc-notice） ==============
server {
    listen 80;
    server_name notic.1008086.xyz;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;

    location / {
        proxy_pass http://127.0.0.1:3111;
    }
}

# ============== 6. qqt.1008086.xyz （qqt 权益抢购公共版） ==============
server {
    listen 80;
    server_name qqt.1008086.xyz;

    root /Users/你的用户名/CMCC-PROJECT/qqt/frontend/dist;
    index index.html;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    client_max_body_size 10m;

    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:7607;
    }
}
```

> 把 `/Users/你的用户名/` 改成你真实的家目录路径（`echo $HOME` 查看）。

### 3.1 nginx 主入口

确保 `nginx.conf` 的 `http {}` 里有：
```nginx
include servers/*.conf;
```

### 3.2 启停命令

```bash
brew services start nginx
sudo nginx -t && sudo nginx -s reload   # 平滑重载
brew services restart nginx             # 完全重启
```

## 5. 公网映射

你的 `home.1008086.xyz` 已经能访问，说明 DNS 已解析到出口 IP。剩下五个子域名照样做 A 记录或 CNAME 到同一目标：

```
rights.1008086.xyz    CNAME  home.1008086.xyz
arpu.1008086.xyz      CNAME  home.1008086.xyz
qqtlocal.1008086.xyz  CNAME  home.1008086.xyz
notic.1008086.xyz     CNAME  home.1008086.xyz
qqt.1008086.xyz       CNAME  home.1008086.xyz
```

> 如果用 frp/cpolar/cloudflare-tunnel 暴露本地 80，确保把 Host 头透传给 nginx；nginx 靠 `server_name` 分流。

### 5.1 HTTPS（可选）

后期上 HTTPS：用 `acme.sh` 申请六个域名证书，nginx 加 `listen 443 ssl;`。
或前面是 cloudflare tunnel 做 TLS 终止，nginx 只跑 80 也行。

## 7. 常见问题

1. **Vite 打包后 `/api` 路径**
   - 这六个项目的前端代码里 `/api` 是相对路径，由 nginx 决定走哪个后端，不会泄露端口。

2. **`cookie-app` Prisma 报 `P1001`**
   - 99% 是 `DATABASE_URL` 没指向 docker 里的 PG，或端口写错。`docker compose ps` 检查。

3. **`qqtlocal` 502**
   - `lsof -iTCP -sTCP:LISTEN | grep 8899`；用 `./run.sh` 会绑定 `0.0.0.0:8899`，nginx 走 `127.0.0.1` 即可。

4. **`arpu` 静态 404**
   - `proxy-server.js` 把根映射到 `arpu.html`，nginx 整体反代就行。

5. **修改前端代码后不更新**
   - 重新 `npm run build`，nginx 不用重载；浏览器 Ctrl+Shift+R 强刷。
